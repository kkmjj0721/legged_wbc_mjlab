# HIMPPO 对称机制原理与 RI-4438 四足接入方案

当前优先分析普通 RI-4438 HIM：它可以接入与普通 PPO 类似的对称数据增强和对称损失，也可以研究去掉显式步态奖励与相位观测后，自主形成四足步态的方案。对称机制有助于学习镜像情境下的一致决策，但不保证形成指定的 trot。开启后的性能收益需要在 RI-4438 上单独验证，不能由其他机器人上的结果直接推出。

设计对象是以 RI-4438 为主的四足运动控制。首选约束是左右反射；保留当前显式对角小跑相位时，需要同步变换相位，真正去掉相位后则使用纯空间镜像。四条腿不能任意互换，前后反射也不能直接套用。HOMIE 的人形实验用于说明 HIM 与对称训练的组合方式；四足的物理映射、步态约束和收益需要分别核验。

本文面向本项目后续实现和实验设计，涵盖当前代码、数学含义、四足镜像规则、HIM 估计器适配及公开项目依据。第十八章给出四足专项设计，第十九章专门分析普通 HIM 的无显式步态方案。前文已完成的 LPACRL 接线、指纹和评价分析作为扩展参考保留，不作为普通 HIM 首轮实验的前提。现有行为按源码说明；新增配置、接口和实施步骤均为拟议设计，不代表已经实现。

“关闭新功能时保持旧训练等价”的目标，适用于保留原观测和奖励、仅新增对称开关的情况。删除相位和步态奖励会改变任务定义及模型输入，需要作为独立实验；不能同时承诺原 47 维模型按原方式直接续训。

### 如何理解不影响现有训练

“功能关闭”和“功能开启”需要分别讨论。

功能关闭时，可以把以下内容作为兼容性目标：相同初始化、相同训练批次、相同随机状态下，网络输出、loss、梯度、优化器更新、归一化统计和日志语义均保持一致。这个目标要由回归测试证明，单凭默认权重设为零并不能保证。

功能开启时，改变优化目标就是功能本身的作用。策略会改变，后续采样数据、KL、自适应学习率以及 LPACRL 采样概率都可能改变。能够保持的是接口、训练流程中的既有职责和模型部署约定，不能同时要求训练参数轨迹也完全相同。

| 使用场景 | 可以保持的内容 | 必须明确的变化 |
| --- | --- | --- |
| 加入支持但保持 `None` | 原有算法路径和模型结构 | 新字段对配置指纹的影响需要兼容 |
| 只开启动作镜像损失 | 环境、奖励、部署输入输出 | 策略梯度改变，训练增加额外前向计算 |
| 开启 PPO 数据增强 | 真实 rollout 数量、环境步数 | 优化时样本数量和计算量增加 |
| 同时增强 estimator | estimator 网络结构和预测接口 | 估计器训练分布及原型分配改变 |
| 旧模型播放和导出 | 参数形状、输入输出及裁剪规则 | 不应为训练功能增加部署依赖 |
| 旧实验完整续训 | 模型、优化器和课程历史 | 仅在训练语义兼容时成立 |
| 用旧权重开启新机制 | 可以复用网络参数 | 应作为新的训练变体记录 |

## 二 对称约束的数学含义

### 观测镜像与动作镜像

定义观测镜像算子 `M_o` 和动作镜像算子 `M_a`。对于当前带历史的策略，`o` 可以理解为整段历史观测，而不仅是一帧。

希望满足的关系是：

\[
\mu_\theta(M_o(o)) \approx M_a(\mu_\theta(o)).
\]

其中 `μθ` 表示策略的确定性动作均值。左边先镜像观测再计算动作；右边先计算动作再镜像动作。两边接近，表示策略在互为镜像的情境下作出相应决策。

以左右镜像为例，向左侧移的指令应变成向右侧移，左前腿的状态应与右前腿交换。原情境下为了支撑而输出的动作，镜像后应该由对应的另一条腿执行。

这个约束比较的是两种输入情境。它允许同一时刻左右腿处于不同的支撑和摆动阶段，也允许机器人在不同外部条件下采取不同动作。

### 等变与不变

策略输出随输入镜像而发生对应变化，称为等变：

\[
\mu(M_o(o))=M_a(\mu(o)).
\]

如果任务和动力学确实具有对应对称性，互为镜像的状态可以具有相同价值，对应价值函数的不变性：

\[
V(M_c(c)) \approx V(c).
\]

`c` 是 critic 的观测，`M_c` 必须覆盖其中的特权信息。策略输出通常需要交换和变号，标量价值则通常保持不变，两种约束的形式不同。

普通 MLP 的结构不自动保证这些关系。对称损失是一种软约束，权重有限时允许偏离；使用对称结构的网络是另一类设计，不在此次兼容接入的范围内。

### 动作对称损失

与本地普通 PPO 一致的基本形式是：

\[
L_{\mathrm{mirror}}
=\frac{1}{BD_a}\sum_{b=1}^{B}\sum_{j=1}^{D_a}
\left[\mu_\theta(M_o(o_b))_j-
\operatorname{sg}\left(M_a(\mu_\theta(o_b))_j\right)\right]^2.
\]

`B` 是原始批次大小，`D_a=12` 是当前动作维数，`sg` 表示停止梯度。固定作为目标的一侧后，另一侧受到直接梯度约束；两侧使用同一个策略网络，参数在后续更新中仍然共同变化。

这里比较动作均值，可以避免独立随机采样带来的差异。如果用两次带噪声的动作样本做比较，即使策略均值已经对称，损失也可能不为零。

这个损失只约束均值，没有单独要求高斯策略的探索标准差也满足左右镜像。即使均值误差很小，也不能据此断言完整动作分布严格等变。

### 与 PPO 目标的关系

本地代码采用最小化形式：

\[
L_{\mathrm{base}}
=L_{\mathrm{surrogate}}+c_vL_V-c_e\mathbb E[H(\pi_\theta)].
\]

加入动作对称项后：

\[
L=L_{\mathrm{base}}+\lambda_a L_{\mathrm{mirror}}.
\]

其中 `λa` 对应 `mirror_loss_coeff`。它直接参与反向传播，不需要把该值写进环境 reward。增加环境奖励与增加训练损失会经过不同的学习路径，也会不同地影响 return、advantage 和课程评价。

损失的归约方式影响系数含义。例如对 12 维动作先求和再对样本平均，会比对所有元素取平均大 12 倍。比较不同项目时，必须同时比较系数、动作尺度、动作维数和归约方式。

### 价值对称损失属于额外扩展

可以另行定义：

\[
L_{V,\mathrm{sym}}
=\operatorname{MSE}(V_\psi(M_c(c)),\operatorname{sg}(V_\psi(c))).
\]

但当前普通 PPO 的 `Symmetry` 扩展没有这个独立项。镜像数据参与 value loss，与显式要求两次 value 输出相等，是两件不同的事。

如果后续添加 critic 对称损失，应有独立配置、独立日志和独立消融，不能把它悄悄纳入“与普通 PPO 一样”的默认实现。

## 三 对称数据增强的含义与假设

### 原始样本与镜像样本

对于原始数据 `(o,a)`，增强构造 `(M_o(o),M_a(a))`。常见排列为：

```text
前 B 行        原始样本
后 B 行        左右镜像样本
```

单个镜像通常把更新批次从 `B` 扩展为 `2B`。这里增加的是从已有数据变换得到的样本，不增加真实环境交互，也不提供新的独立物理信息。

数据增强让 PPO 在两个情境上学习；镜像损失则直接比较两条决策路径。二者可以分别启用，也可以组合。

### 复制 return 和 advantage 的前提

严格的状态对称变换需要同时尊重奖励和转移关系，例如：

\[
r(M_s(s),M_a(a))=r(s,a),
\]

\[
P(M_s(s')\mid M_s(s),M_a(a))\sim P(s'\mid s,a).
\]

还要考虑任务指令、环境参数、初始分布及终止规则。实际机器人通常只能近似满足这些条件，因此将 return 和 advantage 复制给镜像样本，是利用任务对称先验的训练方法，不能自动解释为重新仿真验证过的真实回报。

尤其在策略尚未对称时，不能仅凭环境对称就断言当前策略的 `Vπ(s)` 与 `Vπ(M_s(s))` 严格相等。数据增强的目的之一，正是促进策略向对应一致的方向学习。

### 本地 PPO 如何处理旧概率

本地 `augment_batch()` 复制原样本的旧 log probability、value、advantage 和 return，没有对镜像观测重新计算 rollout 时旧策略的概率。

对带符号的动作置换，可以把旧动作分布一起推送到镜像空间；在这种解释下，原样本的 log probability 可以对应变换后分布中的镜像动作概率。但它不一定等于未经约束的旧网络直接在镜像观测上的输出概率。

这一区别决定实现语义。若以本地普通 PPO 为基准，应保留它的增强约定，并在说明和实验中明确这一点；若改为缓存或重算旧策略的镜像概率，则属于另一种算法设计，需要单独比较。

### 近似对称的实际限制

以下情况会降低精确对称假设的成立程度：

- 左右执行器性能、惯量或传感器误差分布不同。
- 有偏载或固定的单侧附属物。
- 任务要求固定朝某一侧运动，或者世界坐标中的地形方向具有特殊含义。
- 当前观测没有覆盖所有需要镜像的隐变量。
- 相位、reset 时钟和有限回合边界不随镜像一致变换。

这不意味着对称约束一定无效，而是应把它看作强度可调的先验，并通过具体任务结果决定其权重。

## 四 当前普通 PPO 的实现

### 配置与调用路径

普通 PPO 的构造函数接收 `symmetry_cfg`。配置非空时创建 `Symmetry`；算法工厂通过 `resolve_symmetry_config()` 把环境对象传给任务提供的映射函数。详见 [ppo.py](../rsl_rl/algorithms/ppo.py) 和 [symmetry.py](../rsl_rl/extensions/symmetry.py)。

| 字段 | 作用 |
| --- | --- |
| `symmetry_cfg` | 是否创建扩展以及扩展参数 |
| `data_augmentation_func` | 任务定义的观测与动作映射函数 |
| `use_data_augmentation` | 是否让镜像样本参与 PPO 和 value 更新 |
| `use_mirror_loss` | 是否把动作镜像损失加入反向传播 |
| `mirror_loss_coeff` | 动作镜像损失的权重 |
| `env` | 构造时注入的运行时环境对象 |

### 四种模式与完全关闭

| 配置状态 | 数据增强 | 加入镜像损失 | 其他行为 |
| --- | --- | --- | --- |
| `symmetry_cfg=None` | 否 | 否 | 完全不创建扩展 |
| 有配置且两个开关均为假 | 否 | 否 | 计算镜像误差用于日志 |
| 仅数据增强 | 是 | 否 | 镜像误差只记录，不参与梯度 |
| 仅镜像损失 | 否 | 是 | 为计算该损失额外构造镜像观测 |
| 两者开启 | 是 | 是 | 镜像样本参与 PPO，同时施加一致性约束 |

`mirror_loss_coeff=0` 不是最可靠的完全关闭方式：扩展仍可能做额外计算，数据增强也可能独立生效。保证旧路径兼容时，应使用 `None`。

### 一次更新中的次序

普通 PPO 的核心顺序为：

1. 记录原始批次大小，按配置归一化优势。
2. 可选地增强当前批次。
3. 计算策略 log probability、value 和 entropy。
4. 使用原始样本部分计算 KL 和熵统计。
5. 计算 PPO 与 value loss。
6. 计算镜像损失，按开关加入总 loss。
7. 反向传播、梯度裁剪和 optimizer step。

旧分布参数没有被通用增强函数复制，因此第 4 步使用原始样本部分尤其重要。不能在 HIMPPO 中把增广后的 `2B` 个新分布参数直接与 `B` 个旧参数比较。

### 通用扩展会修改传入的批次

`augment_batch()` 会替换批次的部分字段；即使没有开启数据增强，`compute_loss()` 也会在计算前替换 `batch.observations`，使其包含镜像观测。

因此，接入 HIM 时不能把这个对象当成始终保有原始 `B` 个样本的只读容器。应该保留原始批次，并给对称分支构造独立的批次容器；镜像函数也不能原地改写 rollout 的张量。

## 五 当前 HIMPPO 的结构与训练行为

### 实际接线

```text
Ri4438HimLpacrlCfgPPO
    ↓ 复制中央配置
LpacrlCfg.learning
    ↓ 构造 dataclass 配置
RslRlHimAlgorithmCfg
    ↓ class_name
rsl_rl.algorithms.him_ppo:HIMPPO
    ↓ update
PPO actor critic 更新 + HIM estimator 独立更新
```

任务选择 `LPACRLRunner`，runner 在采样和周期评估之间调用 `self.alg.update()`。课程控制器不直接定义 PPO 的梯度目标。[任务 RL 配置](../src/tasks/locomotion/ri_4438_him_lpacrl/config/rl_cfg.py)、[runner](../src/tasks/locomotion/ri_4438_him_lpacrl/rl/runner.py)。

### 网络输入和输出

当前主要维度如下：

| 项目 | 当前维度或设置 |
| --- | --- |
| actor 单帧观测 | 47 |
| actor 历史帧数 | 6 |
| actor 历史总维数 | 282 |
| estimator 显式速度输出 | 3 |
| estimator 隐式 latent | 16 |
| 动作网络输入 | 47 + 3 + 16 = 66 |
| 动作输出 | 12 |
| critic 观测 | 244 |
| 独立 estimator 监督观测 | 50 |

`encoder_hidden_dims=(128,64,16)` 的最后一个值用于定义 latent 维度。当前编码器最终输出为 `3+16=19`，包含速度和隐式表征，不能把整个最终输出误认为只有 16 维。[HIM actor](../rsl_rl/models/him_actor_model.py)、[HIM estimator](../rsl_rl/modules/him_estimator.py)。

### 现有更新次序

每个 mini-batch 中，当前代码先做 actor/critic 前向并计算 KL，再用有效历史与下一时刻目标更新 estimator，最后执行 PPO 的反向传播和参数更新。完成所有 mini-batch 后，用真实 rollout 观测更新 actor 和 critic 的归一化统计。[HIMPPO 更新实现](../rsl_rl/algorithms/him_ppo.py)。

保留这条生命周期具有实际意义。若在加入对称功能时顺便重排 estimator 更新、归一化更新或学习率调整，就无法把训练变化归因于对称机制本身。

### estimator 的目标

估计器的现有目标为：

\[
L_E=L_{\mathrm{velocity}}+L_{\mathrm{swap}}.
\]

速度项比较预测速度和下一时刻监督观测中的真实速度。`swap_loss` 通过历史编码、目标编码和原型分配进行交叉监督，它没有显式的左右交换含义。[估计器损失实现](../rsl_rl/modules/him_estimator.py)。

当前目标切片为：

```text
速度监督                 estimator_obs[47:50]
目标网络的 47 维输入       concat([0:6], [9:47], [47:50])
```

目标网络输入去掉了速度指令 `[6:9]`，保留相位、关节状态和上一动作，并拼入真实线速度。它虽然也是 47 维，但与 actor 单帧 47 维的字段顺序不同。后续不能根据“维度相同”复用同一个平面切片映射。

最稳妥的做法是先镜像完整的 50 维监督观测，再调用现有目标提取逻辑。[目标提取代码](../rsl_rl/algorithms/him_ppo.py)、[监督观测组](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/terminal_observations.py)。

### 梯度边界

HIM actor 通过 `no_grad()` 获取 estimator 输出，估计器自身也返回 detached 的预测。PPO optimizer 虽然包含 estimator 参数，但 PPO loss 不经该路径向 estimator 传播梯度；estimator 由其自己的 optimizer 更新。

若保持这个结构，新增动作镜像损失也不会直接训练 estimator。这个事实与“对 estimator 的输入和监督数据做增强”并不冲突：后者仍然通过 estimator 自己的损失和 optimizer 生效。

## 六 RI-4438 镜像规则

### 坐标系与向量类型

以下规则以机器人坐标系 `x` 向前、`y` 向左、`z` 向上，关于 `x-z` 平面左右反射为约定。基本反射矩阵为：

\[
R=\operatorname{diag}(1,-1,1).
\]

位置、线速度、重力等普通向量使用 `Rv`。角速度属于轴向量，使用 `det(R)Rω`：

\[
(v_x,v_y,v_z)\mapsto(v_x,-v_y,v_z),
\qquad
(\omega_x,\omega_y,\omega_z)\mapsto(-\omega_x,\omega_y,-\omega_z).
\]

因此，不能把 IMU 角速度和重力投影统一按“第二维取负”处理。若以后更换 IMU 朝向，应先核对观测所在的坐标系，再应用这些规则。

### actor 单帧观测映射

下面的切片以当前观测拼接顺序为依据，采用 Python 左闭右开区间。[环境观测定义](../src/tasks/locomotion/ri_4438_him_lpacrl/ri_4438_him_lpacrl_env_cfg.py)。

| 切片 | 内容 | 左右镜像规则 |
| --- | --- | --- |
| `[0:3]` | 机身角速度 | `(-wx, wy, -wz)` |
| `[3:6]` | 重力投影 | `(gx, -gy, gz)` |
| `[6:9]` | `vx, vy, wz` 指令 | `(vx, -vy, -wz)` |
| `[9:11]` | 相位的 sin 和 cos | 当前 trot 约定下两者一起取负 |
| `[11:23]` | 相对关节位置 | 对应腿交换，按关节轴确定符号 |
| `[23:35]` | 相对关节速度 | 对应腿交换，按关节轴确定符号 |
| `[35:47]` | 上一次动作 | 使用动作空间的镜像映射 |

镜像应对全部 6 帧分别执行，保留帧之间的时间顺序。环境侧历史为 oldest-first，actor 内部会调整为 current-first；空间镜像函数不应额外倒转一次时间轴。

观测已有的噪声和延迟应随对应分量一起变换，不能为镜像副本重新随机生成一段与原历史无关的误差，否则就改变了增强操作的含义。

### 对应腿与关节轴

腿的对应关系是 `FL ↔ FR`、`RL ↔ RR`。当前资产的 hip 关节轴为 `x`，thigh 和 calf 关节轴为 `y`，可推导候选关节变换：

| 关节类型 | 交换到对应腿后的符号 |
| --- | --- |
| hip | 取负 |
| thigh | 保持 |
| calf | 保持 |

依据：[RI-4438 资产](../src/assets/robots/ri_4438/xmls/ri_4438.xml)。这是一套由轴定义推导出的映射，后续仍应通过对应足端位置和实际运行时关节索引进行验证。

不能假定动作向量排列必然等于 XML 中的关节排列。当前 actuator 按 hip、thigh、calf 分组配置，环境解析后应分别读取观测关节顺序和 action term 的实际顺序，按名称建立置换，再缓存为张量。[资产配置](../src/assets/robots/ri_4438/ri_4438_constants.py)。

### 相对关节位置与动作缩放

设 `T_q` 为带符号的关节置换，绝对关节角为 `q`，默认姿态为 `q0`。若观测是 `δq=q-q0`，则：

\[
\delta q'=T_q\delta q+T_q q_0-q_0.
\]

只有默认姿态满足 `T_q q0=q0` 时，才能简化成纯置换和变号。当前 hip 默认角为零，thigh 和 calf 的左右默认角相同，符合这项简化条件。[中央默认姿态](../src/config/ri_4438/ri_4438_him_lpacrl_config.py)。

对于 `q_des=q0+D a` 形式的位置动作，镜像动作应满足：

\[
a'=D^{-1}\left[T_q(q_0+Da)-q_0\right].
\]

当前对应左右关节使用相同缩放，因而可以简化为对应腿交换及符号变化。以后如果加入左右不同的零位或 action scale，应重新推导，不能继续沿用旧映射。

### 步态相位为什么要平移半周期

当前足顺序为 `FL, FR, RL, RR`，相位偏移为：

```text
FL      FR      RL      RR
0.0     0.5     0.5     0.0
```

期望接触状态按 `((φ+offset) mod 1) < threshold` 计算。左右交换后，两组对角支撑腿互换。取 `φ'=φ+0.5 mod 1`，就能让期望接触标签随腿交换而对应变化。

当前相位编码是：

\[
(\sin 2\pi\phi,\cos 2\pi\phi).
\]

因此半周期平移对应两个分量同时取负。停止运动时相位编码被置零，取负后仍为零。[步态配置](../src/tasks/locomotion/ri_4438_him_lpacrl/config/env_cfgs.py)、[相位观测](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/observations.py)、[步态奖励](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/rewards.py)。

这是空间反射与相位平移的组合，不要求把机器人真的向未来推进半个周期，也不能把历史帧循环移位来实现它。

不过，相位平移并不自动保证整个有限回合过程精确对称。相位来自回合时钟，reset 后通常回到同一起点；镜像后的半周期初相位未必属于原始 reset 分布。实现应保证局部观测与奖励的对应关系，并把有限时域及 reset 分布的差异视为近似对称的边界。

### critic 和 estimator 观测

当前 critic 是 actor 单帧字段加上特权信息，总宽度 244：

| 切片 | 内容 | 镜像规则 |
| --- | --- | --- |
| `[0:47]` | 单帧基本字段 | 同 actor 单帧语义，但使用 critic 的真实观测 |
| `[47:50]` | 机身线速度 | `(vx, -vy, vz)` |
| `[50:53]` | 躯干局部质心偏移 | `(cx, -cy, cz)` |
| `[53:57]` | 四足接触状态 | 按实际传感器顺序交换左右足 |
| `[57:244]` | 187 点高度扫描 | 根据射线位置交换左右采样点 |

这里的 `base_com` 读取的是局部 `body_ipos`，不应当作世界坐标位置处理。独立 estimator 观测组只有前 50 维，不含质心、接触和地形扫描。[观测实现](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/observations.py)、[监督观测配置](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/terminal_observations.py)。

### 地形扫描的映射

当前扫描尺寸为 `1.6 m × 1.0 m`，分辨率 `0.1 m`，共 187 点。当前安装的 `GridPatternCfg` 使用 `meshgrid(..., indexing="xy")`，按该实现和配置，网格可以理解为 `11 × 17`，左右镜像对应翻转 `y` 所在的行轴，保留 `x` 方向次序。

更可靠的工程实现是直接读取每条射线的局部位置，为 `(x_i,y_i)` 找到 `(x_i,-y_i)` 对应索引，并检查一一对应。这样可以显式发现网格偏移、排列变化或采样区域本身不对称的问题。

不能把 187 维向量整体倒序当作左右镜像：整体倒序往往同时反转前后与左右。高度值本身是标量，重排采样位置即可，不应将高度取负。

### 隐式 latent 的处理

速度具有明确的物理变换，但 16 维 latent 的每一维没有预先指定的空间含义。不要手工规定 latent 的某几个维度取负或交换，也不要直接强迫镜像前后的 latent 完全相同。

动作镜像分支应将镜像后的原始历史重新送入 estimator，得到该历史对应的速度和 latent。若以后设计 latent 等变结构，应作为独立研究问题，与此次动作空间约束分开。

## 七 建议的接入边界

### 第一阶段对齐本地 PPO 的功能

第一阶段可以完整支持两个已有开关，同时保留 estimator 的原始监督路径：

| 模块 | 第一阶段行为 |
| --- | --- |
| actor 的 PPO 目标 | 可选使用原始与镜像样本 |
| critic 的 value 目标 | 开启数据增强时使用原始与镜像样本 |
| actor 镜像损失 | 独立开关控制 |
| critic 显式镜像损失 | 暂不加入 |
| estimator loss | 维持现有速度项和 swap 项 |
| estimator 数据 | 使用原始有效样本 |
| rollout storage | 继续只保存真实交互序列 |
| 环境 reward 与 termination | 保持现有定义 |
| LP 统计与评价任务 | 继续基于真实 rollout 和独立评估 |

这个范围实现的是“与当前普通 PPO 类似的对称机制”。它不是完整复现 HOMIE 的所有设计，两者需要在实验命名和结果解释中区分。

### 第二阶段可选的 estimator 数据增强

第二阶段可以同步镜像历史和完整下一时刻监督观测，再构造估计器训练批次：

```text
原始历史 h                 → 原始下一时刻监督 e_next
镜像历史 M_h(h)            → 镜像下一时刻监督 M_e(e_next)
```

这个配对关系必须保持。不能用镜像历史预测未镜像的侧向速度，也不能因为目标网络输入也是 47 维，就用 actor 的字段切片去镜像它。

估计器有效性掩码应与这两组样本一一对应。可以先筛选有效原始样本再镜像，或者同时扩增掩码后筛选；两者应有明确的等价性测试。`done=True` 不等于 estimator 样本一定无效：若存在正确的 terminal observation，当前代码仍可把该终止步作为有效监督。

### 第三阶段可选的 critic 对称项

critic 对称损失进一步要求价值输出在镜像状态间一致。由于当前 critic 可见地形、质心和足接触，它需要更完整的映射验证。

这个选项可能改变 critic 对不对称策略和任务分布的拟合，应与第一阶段的 actor 镜像损失分开调参。将其加入总 loss 时，采用独立系数 `λv`，而不是默认与 `λa` 共用一个数值。

### 三种扩展目标的区别

| 目标 | PPO 数据增强 | actor 镜像损失 | estimator 增强 | critic 镜像损失 |
| --- | --- | --- | --- | --- |
| 保留现有基线 | 关 | 关 | 关 | 关 |
| 对齐本地 PPO 能力 | 可选 | 可选 | 关 | 关 |
| 研究 HIM 完整增强 | 可选 | 可选 | 可选 | 可选 |

完整功能支持与首次实验开启哪些开关是两个决定。可以一次把第一阶段的两个开关都接好，但先用较小实验确认每个分支，再安排组合对照。

## 八 HIMPPO 更新过程的适配设计

### 批次容器的职责

原始 HIM 批次要作为所有分支的共同依据。建议在更新函数中明确以下三个容器或视图：

| 容器 | 样本数量 | 用途 |
| --- | --- | --- |
| 原始批次 | `B` | 原始数据、旧分布参数和 estimator 监督配对 |
| PPO 工作批次 | `B` 或 `2B` | PPO 与 value loss |
| 对称比较批次 | 原始与镜像成对 | 动作均值比较及对称诊断 |

容器可在不修改底层张量时共享只读数据，但任何置换、变号、拼接都应产生独立输出。尤其不能让通用扩展对 `observations` 的替换影响原始 estimator 分支。

新增 estimator 增强时，也应从原始批次构建 `2B` 个样本，不能从已经增广的 PPO 批次再增广成 `4B`。重复增强会改变原型分配和优化权重，还会使训练成本难以解释。

### KL 和熵使用哪些样本

以本地普通 PPO 的行为为准，KL 和熵统计使用原始前 `B` 行。镜像样本的 PPO loss 可以存在，但不能让镜像扩展意外改变 KL 的配对关系。

旧分布参数、当前分布参数、动作 log probability 的长度各自要有断言。不能依赖 broadcasting 让形状错误悄悄通过，尤其是某些批次恰好只含一个样本时。

### estimator 更新前后的参数版本

当前一轮 mini-batch 内 estimator 会更新一次。若动作镜像比较的一侧在更新前计算，另一侧在更新后计算，差异就混入 estimator 参数变化，不再只是镜像一致性误差。

可采用两种清晰的方案：

1. 在 estimator 更新前，完成镜像比较的两侧前向，并保留 actor 计算图；随后按原顺序更新 estimator，再对合成的 PPO loss 反向传播。
2. 在 estimator 更新后，同时重新计算两侧前向，并只在这个一致的参数版本上计算镜像项。

第一种使镜像项和原始 PPO 前向共享同一 estimator 版本；第二种需要接受镜像项与先前 PPO 前向使用不同 estimator 版本。两种方案都必须保证镜像项自己的两侧一致，并在实现中固定下来。

若以最小化生命周期变化为目标，优先考虑第一种。其可行性依赖 estimator 输出已经 detached，不向其参数保留反向图。仍需测试优化器更新过程中没有修改被 actor 图依赖的中间张量。

### 动作均值与裁剪

本地普通 `MLPModel` 的确定性高斯输出对应原始均值，而当前 `HIMActorModel.forward(..., stochastic_output=False)` 会在返回前执行动作裁剪。LPACRL 的 `ACTION_CLIP` 当前为 10。

直接将 HIM actor 传给现有 `compute_loss()`，会改变损失含义。例如原始输出 12 与 20 都裁剪为 10，对称误差可能被掩盖；裁剪区间外的梯度也可能消失。

拟议处理是为训练提供一个无随机采样、返回裁剪前均值的入口，或给通用扩展传入等价的均值计算适配器。这个入口应保持 estimator 的 detached 语义，不注册新的可训练网络，不改变 `state_dict` 的已有键，不更改 `act_inference`、ONNX 和真实环境动作裁剪。

还要避免为了获取均值而额外调用会采样的 `act()`，否则会消耗随机数并改写分布缓存。对称前向需要均值，不需要重新生成探索噪声。

### 归一化位置

正确的运算关系是：

\[
o\xrightarrow{M_o}o'\xrightarrow{\mathrm{normalizer}}\tilde o'
\xrightarrow{\mathrm{policy}}a'.
\]

一般不能把归一化后的向量简单镜像来代替该过程，因为逐维均值和标准差可能不对称：

\[
N(M_o(o))\neq M_o(N(o)).
\]

第一阶段应保留当前归一化统计的更新时间和数据来源：在 PPO epoch 完成后，仅从真实 rollout 更新。对称 loss 中额外前向不应更新统计，镜像数据是否也参与统计应作为之后的独立选择。

当前 `EmpiricalNormalization.forward()` 只使用统计，`update()` 才修改它们，这有利于隔离新增分支。[归一化实现](../rsl_rl/modules/normalization.py)。

### 梯度与共享裁剪的影响

即使只加入 actor 镜像损失，也不能声称 critic 的实际参数步长一定不变。当前代码对 actor 和 critic 的参数集合统一进行梯度范数裁剪；新增 actor 梯度可能改变整体范数，从而改变 critic 梯度受到的共同缩放。

因此，更准确的描述是：actor 镜像项不直接向 critic 提供梯度，但共享的优化步骤和后续训练数据可能产生间接影响。为维持现有优化器语义，不应在同一次改动中顺便拆分全局梯度裁剪。

对 estimator 梯度的验证，也应清理原有 `.grad` 后独立反向传播镜像项。只检查一次常规更新后的 `.grad` 是否非空，会把 estimator 自己更新留下的梯度误当成镜像梯度。

### 设计级伪代码

以下展示职责与先后关系，函数名仅用于说明，不是当前可执行接口：

```text
取出原始 HIM mini-batch

若完全关闭对称功能
    执行现有更新流程
否则
    保留原始 B 和原始 estimator 数据配对
    从原始批次构造独立 PPO 工作批次
    按开关对 PPO 工作批次做镜像增强

    计算 PPO actor critic 前向
    用原始 B 行计算 KL 和熵
    更新自适应学习率

    在同一 estimator 版本下计算镜像比较两侧
    准备现有 estimator 监督数据
    如启用 estimator 增强 同步变换历史与下一时刻目标
    执行一次 estimator optimizer step

    组合 PPO loss 与按开关启用的对称项
    PPO optimizer 清理梯度
    反向传播和原有梯度裁剪
    执行一次 PPO optimizer step

所有 mini-batch 完成后
    按现有逻辑更新真实 rollout 的归一化统计
    清空 storage
```

### 终止观测与 timeout 保持原有职责

当前任务有 reset 前的 estimator 观测采集和有效性掩码，处理真实终止观测与自动 reset 之后的观测差异。对称变换应发生在这套逻辑已经识别好正确监督目标之后。

镜像样本不应该重新定义 `done`，也不应该把已无效的下一时刻数据变成有效数据。现有 timeout 奖励补偿、边界截断和失败优先级不属于对称功能，应保持其现有语义。[terminal recorder](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/terminal_observations.py)、[HIMPPO 环境步处理](../rsl_rl/algorithms/him_ppo.py)。

`curriculums.py` 中的 LP 计算和 `evaluator.py` 中的评价任务不需要为镜像 loss 改公式。新的镜像质量指标可以独立增加，但不应自动进入原来的课程回报。

共享 HIMPPO 中不应硬编码 RI-4438 的 47 维切片和关节名称。映射由任务配置传入，其他 HIM 任务缺省为 `None`。

### 配置验证

启用时应检查映射函数可解析、系数有限且非负、观测布局和机器人名称集合匹配。对“已请求启用但映射缺失”的情况应明确报错，不能继续静默丢弃配置。

运行时环境引用应只注入复制后的算法构造配置。保存的配置、用于哈希的配置和中央配置应保持可序列化，避免把环境对象或 GPU 张量放入指纹。当前 `resolve_class()` 已对配置做深复制，可沿用这一边界。[配置解析工具](../rsl_rl/utils/utils.py)。

## 十 旧模型与 LPACRL 续训兼容

### 模型权重兼容

对称训练本身不要求改变 actor、critic 或 estimator 的网络尺寸。只要不增加可训练层、不改变参数名称、保持归一化和输入输出约定，旧模型参数可继续加载，部署可以继续执行一次普通确定性前向。

训练用的镜像映射可以保存在算法或任务辅助对象中，不应成为部署所需的额外输入。若为映射添加模块 buffer，应考虑 `state_dict` 的持久化行为，避免旧 checkpoint 因多出必需键而无法严格加载。

### 优化器兼容

保留原参数集合和顺序时，对称 loss 不必改变 optimizer state 的结构。不要为了接入功能随意重组参数组、删除 estimator 参数或新增 optimizer，因为这些变化会影响现有状态加载。

开启新损失后，继续使用旧 optimizer 状态在数值上可能可行，但实验含义已经变化。是否保留其动量应是明确的实验选择，而不应由兼容代码隐式决定。

### 当前有两处相关配置指纹

LPACRL 不仅核对权重，还核对训练配置：

- `fingerprints["him"]` 包含 `cfg.learning` 等中央配置快照。
- `fingerprints["agent"]` 包含实际 actor、critic、algorithm、动作裁剪、观测组和数值配置。

两处都可能受新增 `symmetry_cfg=None` 影响。旧配置没有该键，新配置有该键，即使训练路径相同，直接 JSON 哈希也会不同。只修 agent 指纹而忽略 him 指纹，仍可能拒绝旧实验续训。[课程指纹](../src/tasks/locomotion/ri_4438_him_lpacrl/config/curriculum_cfg.py)、[agent 指纹与加载](../src/tasks/locomotion/ri_4438_him_lpacrl/rl/runner.py)。

### 兼容规范化的边界

可设计一个作用范围很窄的规范化规则：在计算相关指纹前，将已明确证明等价的新增关闭字段折叠成旧配置表示，例如删除值为 `None` 的新 `symmetry_cfg` 字段。

不要把所有 `None`、所有 `False` 或整个 algorithm 字段从指纹中删除。已有字段可能表达重要语义，宽泛删除会让真正不兼容的配置被接受。

有配置但仅记录镜像误差的模式，至少增加了计算和日志；默认不要未经验证就把它视为旧版的完全关闭状态。真正开启增强或 loss 的配置必须保留在指纹里。

映射函数字符串也不足以描述全部语义：相同路径下的代码可能改变。启用时宜额外记录镜像规则版本和实际索引布局的摘要，便于判断相位规则、关节置换或高度图排列是否发生变化。

### resume 与 warm start

| 情况 | 合理处理 |
| --- | --- |
| 旧实验没有对称配置，新程序保持关闭 | 经严格的缺省兼容规则后允许完整续训 |
| 新实验启用某组对称参数，之后配置不变 | 支持完整续训并保留 optimizer 和课程历史 |
| 旧实验关闭，准备开启对称训练 | 按当前项目规则使用 warm start 开始新变体 |
| 已开启实验改变权重或映射语义 | 视为训练配置变化，不能伪装成完全相同实验 |
| 只播放旧模型 | 按现有 actor-only 流程，保持数值契约与任务校验 |

当前 `warm_start()` 加载模型权重，但不恢复 PPO optimizer、estimator optimizer 和旧课程进度。它是重新开始训练实验，不等同于完整 resume。[warm start 实现](../src/tasks/locomotion/ri_4438_him_lpacrl/rl/runner.py)。

如果以后需要“改变训练目标但保留部分 optimizer 和课程状态”的迁移方式，应该另行定义显式操作和元数据。不要通过跳过指纹校验来实现。

### 可证明的兼容程度

首先证明算法在固定输入下关闭等价，再检查 checkpoint 与部署兼容。端到端 GPU 训练的逐位重复还受并行归约、仿真和运行环境影响，不能只凭几次学习曲线相似就证明完全一致，也不能把已有非确定性误认成新增机制必然有问题。

## 十一 对 LPACRL 与实验统计的影响

### 课程公式可以保持原样

当前 LP 使用相邻评估回报差分，并通过温度控制的 softmax 和均匀混合更新任务采样概率；ALP 模式使用差分绝对值。[课程状态更新](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/curriculums.py)。

新增镜像 loss 不必改变这个公式。但策略在每类任务上的进步会变化，因此 LP 值和采样概率也会变化。这是新策略与原课程系统相互作用的结果，需要纳入完整系统评价。

### 镜像样本不能计入真实任务完成次数

PPO 中从一个 rollout 样本构造出的镜像副本，没有执行新的环境步，也没有完成新的 episode。不能让它增加真实环境步数、自然回合计数、任务成功次数或 LP 评估试验数。

当前任务的 `num_steps_per_env`、更新计数、评估间隔和 save interval 应继续按真实采样及原有更新时钟计算。为第一阶段采用更新时增强，可以避免改动 storage 时间轴和 GAE 的递推语义。

### 当前默认镜像仍在同一任务箱内

当前中央配置将 `vx` 和 `wz` 按绝对值分箱，符号在箱内按正负各一半采样；`vy` 在 `[-0.5, 0.5]` 连续采样，`sign_as_task_axis=False`。左右镜像保持 `vx`，将 `vy` 和 `wz` 取负，因此在保留同一地形类别及等级标签的前提下，默认仍属于同一个任务箱。Rough 的 600 个任务不会因该增强变成 1200 个。[中央配置](../src/config/ri_4438/ri_4438_him_lpacrl_config.py)、[任务编译和命令采样](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/task_catalog.py)

任务标签相同不代表固定地形实例已经被镜像，也不代表左右方向实际表现相同。箱内平均评估回报可能掩盖单侧退化，应增加按 `vy`、`wz` 符号分组的诊断，保持原 LP 更新公式不变。

### 将来按方向分箱时的处理

如果任务表将左右速度或转向符号拆成不同任务，镜像观测中的指令可能属于另一个任务 ID。镜像增强可以为该方向提供训练信息，但不能把原任务的真实回报登记成另一个任务的实测表现。

因此，镜像分支仅处理训练数据，不调用课程的任务采样或成绩提交。各任务的真实表现仍应由固定试验表独立评估。

### 两层对照实验

若要区分算法收益与课程反馈收益，可以安排两层实验：

1. 在固定或统一的任务采样分布下，对比对称开关，观察优化本身的效果。
2. 在正常 LPACRL 下重复对比，观察策略和课程共同作用后的整体效果。

只做第二层也可以回答“完整系统是否更好”，但不能把全部变化归因于局部 mirror loss。记录每类任务的采样概率轨迹，可以帮助解释这种反馈。

## 十二 已有公开项目与验证证据

### 四足研究与 HIM 接入证据需要分别看

HIM 原论文研究四足运动控制，并通过本体感知学习显式速度和隐式表征；它可以作为四足 HIM 的依据，不能仅凭这一点就认定原算法已经验证了本文新增的对称项。[HIM 论文](https://arxiv.org/abs/2312.11460)、[官方仓库](https://github.com/InternRobotics/HIMLoco)

下列资料补充了四足方向的依据，但它们与本项目的算法、任务和机器人并不相同：

| 资料 | 机器人与方法 | 可以支持的判断 | 与当前任务的差别 |
| --- | --- | --- | --- |
| [SymmLoco 官方实现](https://github.com/HybridRobotics/SymmLoco) | CyberDog2 任务；普通 PPO、数据增强、等变网络 | 四足平台已有对称强化学习的公开实现 | 部分任务采用后腿直立，不等同于四足 trot；不是 HIMPPO |
| [SGMA 论文 v4](https://arxiv.org/html/2502.01521v4) | ANYmal D 与 G1；对称经验和记忆增强 | 四足的历史上下文处理会影响增强效果 | 使用 RNN 记忆，不是当前 HIM 的有限历史估计器 |
| [Learning Symmetric and Low-Energy Locomotion](https://faculty.cc.gatech.edu/~turk/paper_pages/2018_symmetric_locomotion/index.html) | 包含四足的仿真角色；镜像损失与课程 | 对称动作损失并非仅适用于人形 | 仿真角色实验不等于 RI-4438 实机验证 |
| 下文 HOMIE | 人形；HIM 与对称训练 | 最接近的 HIM 算法组合参考 | 机器人形态及奖励设计不同 |

SymmLoco 论文比较增强和等变网络等方法，覆盖推门、运球、直立转向和直立坡行。它对左右反射和相位处理有参考价值，不能把其中的“坡行”直接理解成本项目四足粗糙地形小跑的验证。[论文任务定义](https://arxiv.org/html/2403.17320v2#S5)

SGMA v4 报告 ANYmal D 的故障、偏载仿真实验和故障条件下的实机结果。其关键发现是缺少上下文推断时，增强可能降低已见任务性能；镜像序列必须形成匹配的记忆。对本项目的设计启示是重新编码完整镜像历史，但这不证明 6 帧 HIM 已具备相同适应能力。[论文方法与实验](https://arxiv.org/html/2502.01521v4)

因此，现有证据应表述为“四足对称学习有公开研究，HIM 加入对称机制也有公开实现”。本次核查没有确认一个同时满足 RI-4438、当前 HIMPPO、当前 trot 奖励和 LPACRL 的现成验证项目，不能把两类证据合并成已经复现的结论。

### 官方 HOMIE 的实验依据

[OpenHomie 的 HomieRL](https://github.com/InternRobotics/OpenHomie/tree/main/HomieRL) 是基于 HIMLoco 和 Isaac Gym 的官方训练实现，面向人形行走、下蹲和上肢运动下的平衡控制。[官方说明](https://github.com/InternRobotics/OpenHomie/blob/main/HomieRL/README.md)

HOMIE 论文 v2 的第四章及图 6 第三行比较了以下设置：

| 设置 | 数据增强 | 对称损失 |
| --- | --- | --- |
| `none` | 关 | 关 |
| `w/ sym` | 关 | 开 |
| `w/ aug` | 开 | 关 |
| `ours` | 开 | 开 |

每组使用 3 个随机种子，在 1000 个环境中进行 20 秒评价。作者报告增强改善训练效率，对称损失降低左右不一致，组合方案的整体跟踪表现略优于仅增强。[论文 v2 的消融实验](https://arxiv.org/html/2502.13013v2#S4.SS1.SSS1)

### 官方 HIMPPO 源码的直接依据

以下以 OpenHomie 提交 `33071f79f1884bb122bd45631c8c60d61dac1eb8` 为定位基准，避免主分支更新后行号和行为漂移。

该版本 `HIMPPO` 包含 actor 和 critic 镜像损失，并将镜像历史与镜像下一时刻观测配对用于 estimator 更新。actor 项按动作维求和后取批次平均，两侧均保留策略梯度；critic 项对一侧停止梯度。[固定版本算法](https://github.com/InternRobotics/OpenHomie/blob/33071f79f1884bb122bd45631c8c60d61dac1eb8/HomieRL/rsl_rl/rsl_rl/algorithms/him_ppo.py)

另一个移植注意点是，该算法版本的 `act()` 和 `process_env_step()` 中镜像路径没有统一由 `use_flip` 包围。因此不能把该开关直接当成本项目“关闭后严格等价”的实现模板；也不能仅靠修改这一个开关，就断言复现了论文全部消融设置。[同版算法的采样路径](https://github.com/InternRobotics/OpenHomie/blob/33071f79f1884bb122bd45631c8c60d61dac1eb8/HomieRL/rsl_rl/rsl_rl/algorithms/him_ppo.py#L94)

上述差异支持一个工程选择：参考其 HIM 与镜像机制组合的思路，但以本地 PPO 的 batch 增强约定为第一阶段实现基准，不直接替换本地算法和 storage。

## 十三 为什么不能直接沿用别人的超参数

### 损失尺度

同名 `symmetry_scale` 或 `mirror_loss_coeff` 不代表相同的约束强度。必须检查动作维数、MSE 是 mean 还是 sum、动作单位、动作缩放、裁剪位置、是否同时约束 critic，以及参与计算的镜像数量。

以当前 12 维动作举例，若每个分量平均平方误差为 `0.01`，对所有分量取平均的 loss 为 `0.01`；先对动作维求和再对样本取平均的 loss 为 `0.12`。即使系数相同，总梯度量级也可能差很多。

梯度强弱还取决于网络局部导数，不能只比较两个标量 loss 的数值。PPO surrogate 的均值有时接近零，但这不意味着其梯度也接近零。

### 训练分布与机器人差异

HOMIE 的人形机器人任务包含上肢扰动和高度控制；当前任务包含四足相位、地形扫描和基于学习进展的采样。它们的状态覆盖、动作含义和奖励平衡不同。

首轮系数选择应基于 RI-4438 实际观测到的原始镜像误差、加权镜像项、PPO 梯度和训练稳定性。可以使用少量候选系数进行受控比较，但候选值只是工程搜索范围，不能写成公开论文为 RI-4438 验证过的参数。

### 计算成本

只开镜像 loss，通常会增加原始与镜像输入的策略前向；数据增强会增加 PPO 和 critic 参与更新的样本。HIM 的额外前向还包含 estimator 的推理，即使这部分没有梯度也需要计算。

若同时增强 estimator，会额外增加其编码器、目标网络、原型打分和反向传播的开销。它的 Sinkhorn 分配依赖整个批次，镜像样本会改变原型分配，不能把结果简单理解为“原 loss 复制一份再取平均”。

不能先验承诺总耗时翻倍或完全不增加：环境仿真、评估、GPU 利用率和数据复制的占比都不同。实验应报告真实环境步数、更新次数、墙钟时间及峰值显存。

## 十四 实施后的验证方案

本章是未来实施的验收规格。文档交付不等于这些训练或回归检查已经通过。

### 变换自身的测试

| 验证项 | 目的 |
| --- | --- |
| 对观测连续镜像两次恢复原值 | 检查置换与符号组合 |
| 对动作连续镜像两次恢复原值 | 检查动作空间映射 |
| 输出的 dtype、device 和形状正确 | 避免训练中隐式转换和设备拷贝 |
| 原输入张量未改变 | 保护 rollout 与原始 estimator 配对 |
| 原始切片始终位于输出前 `B` 行 | 保证 KL、entropy 和目标索引正确 |
| `obs=None` 和 `actions=None` 分别可用 | 符合通用扩展的调用方式 |
| 每帧独立镜像，时间顺序不变 | 防止把历史反转当作空间反射 |
| 未知观测布局和缺失关节明确报错 | 防止旧映射静默适用于新配置 |

仅通过“两次镜像恢复”不够。例如把整段高度图倒序两次也能恢复，但第一次可能把前后一起翻转。需要额外的语义测试。

### 物理语义测试

构造有区别的标记输入，明确检查各字段去向。前进指令保持符号，侧移和转向指令变号；角速度的 roll 和 yaw 变号，pitch 保持；足接触中的左前标记应转移到右前。

为高度扫描构造只依赖 `x` 的测试地形信号，左右镜像后应保持；构造只依赖 `y` 的信号，应交换两侧；再用单点标记确认网格角点对应关系。

关节映射可以在若干非零姿态上检查对应足端相对位置，验证 hip 符号和左右腿索引。使用对称默认姿态是基础检查，但不足以发现所有关节置换错误。

相位测试应覆盖完整周期和接触阈值附近，验证左右足交换与半周期平移保持期望接触标签对应。停止命令下的零相位也要单独覆盖。

### 关闭功能的回归

对比改动前实现和改动后 `symmetry_cfg=None` 的实现，使用同一组模型参数、optimizer 状态、归一化状态、rollout 数据和 RNG 状态。

至少比较：

1. 更新前动作、value、log probability 和 KL。
2. estimator 速度 loss、swap loss、有效样本数量和学习率。
3. PPO surrogate、value loss、entropy 和总梯度范数。
4. 更新后 actor、critic、estimator 的参数。
5. 两个 optimizer 的状态和归一化统计。
6. 更新后的 RNG 状态以及 storage 清理行为。

优先在可控的固定批次测试中要求精确一致；对存在底层非确定性的数值路径，需给出明确容差和原因。通过这一层之后，再做短程环境训练检查。

### 开启功能的梯度验证

对一个人为构造的不对称策略，镜像误差应该非零；在简化可控样例中优化该项，误差应下降。对按构造已等变的策略，误差应接近零。

单独反向传播动作镜像项时，应确认 actor 动作网络获得梯度，而 estimator 参数和 critic 参数没有来自该项的直接梯度。对停止梯度目标一侧的行为，应通过输入或中间输出的梯度检查确认，不能仅看共享网络参数是否有梯度。

另设越过 `ACTION_CLIP` 的均值样例，确保训练用 loss 仍能区分裁剪前的不同输出，同时部署路径继续裁剪。

### 所有开关组合

| 模式 | 必须验证 |
| --- | --- |
| 完全关闭 | 与旧算法更新等价 |
| 仅日志 | 无额外优化目标，基础参数更新保持一致 |
| 仅镜像 loss | PPO 批次仍为原始大小，镜像项确实参与梯度 |
| 仅 PPO 增强 | PPO 批次扩展，estimator 配对和 KL 长度仍正确 |
| 两者同时开启 | 不重复增强，损失统计正确 |
| estimator 增强 | 历史、下一观测、目标切片和有效掩码完全对应 |
| critic 对称项 | 特权观测映射正确，独立系数和日志生效 |

“仅日志”虽然不加 loss，也要测试额外前向没有修改分布缓存、归一化状态或随机数。否则它可能在不明显改变代码结构的情况下影响训练。

### 终止样本和批次边界

覆盖普通步、真实失败、timeout、边界截断、带 terminal observation 的 done、缺少 terminal observation 的 done，以及一个批次中完全没有有效 estimator 样本的情况。

如果将来需要支持共享 HIMPPO 的多 GPU 路径，还要覆盖某个 rank 没有有效 estimator 样本、另一个 rank 有有效样本的情况。当前 LPACRL runner 限定单 GPU，因此不应把单 GPU 验收结果写成整个共享算法已通过多 GPU 验证。

### checkpoint 与部署测试

- 旧配置缺字段与新配置 `None` 的指纹兼容。
- 同一开启配置可以保存和恢复完整训练状态。
- 开启状态改变系数或映射版本时，完整 resume 能正确拒绝。
- 旧模型 actor-only 播放正常，输入输出维度和数值约定不变。
- warm start 按既有规则恢复模型并重新开始 optimizer 和课程。
- PyTorch 与 ONNX 的历史排列、动作裁剪和输出在约定容差内一致。

### 回归范围

共享代码改动后，应覆盖普通 PPO、RI-4438 HIM、Go2 HIM 和当前 LPACRL 的相关构造及关闭路径。对其他任务无需强制新增镜像配置，也不应让它们依赖 RI-4438 专属映射模块。

## 十五 训练对照与评价指标

### 核心实验矩阵

先保持 estimator 不增强、critic 不加独立镜像项，只比较与普通 PPO 对齐的四组：

| 实验 | PPO 增强 | actor 镜像 loss | estimator 增强 | critic 镜像 loss |
| --- | --- | --- | --- | --- |
| 基线 | 关 | 关 | 关 | 关 |
| 动作约束 | 关 | 开 | 关 | 关 |
| 数据增强 | 开 | 关 | 关 | 关 |
| 组合 | 开 | 开 | 关 | 关 |

在某个效果稳定的组合上，再分别加入 estimator 增强与 critic 对称项。这样能够判断收益来自哪部分，而不是只能得到“所有东西一起开以后变好了”的结果。

### 公平比较的预算

各实验保持网络尺寸、奖励、任务定义、初始化策略、环境数量、真实 rollout 长度和评价协议相同。若使用旧权重初始化，应让对照组也从同一权重开始，并明确 optimizer 是否恢复。

对称增强增加了每次更新的训练样本量，因此同时报告两种横轴：真实环境交互步数和墙钟时间。固定环境步数下更好，不能自动等同于固定训练时间下更好。

先用少量短程运行验证实现，再对正式比较使用多个独立训练种子。具体种子数与预算应在看结果前确定；至少 3 个可作为初步工程对照，但不意味着所有差异都已经具有统计确定性。

### 任务表现

优先沿用现有独立评估器的指标，避免为新方法临时修改成功定义：

- `vx`、`vy`、`wz` 跟踪误差。
- 存活时间和物理失败率。
- 边界截断及越界相关统计。
- 不同地形、速度区间和指令方向的分组表现。
- 整体任务覆盖与最困难任务的表现。

总 reward 可以保留，但不应单独作为判断依据。某个对称项可能降低镜像误差，同时恶化转弯、侧移、地形通过或扰动恢复。

### 对称质量

在固定观测集上测量未加权的动作均值镜像误差，分别统计整体、每条腿和各关节类型，并按运动指令及地形分组。

策略离线镜像误差和实际行为左右差异应同时观察。例如，在成对的正负侧移或转向指令下比较跟踪误差、失败率和动作幅值。离线误差很小，不保证闭环行为一定好。

成对的实际环境实验应说明地形、初始状态和扰动是否真的成对镜像。只改变指令符号、保留一块不对称地形，得到的是方向性能比较，不能称为严格的物理镜像实验。

### 训练诊断日志

建议在开启时记录下列诊断；关闭时保持已有 loss 字典和日志含义：

| 指标 | 用途 |
| --- | --- |
| 原始动作镜像 MSE | 观察策略一致性，不混入系数 |
| 加权动作镜像项 | 观察它对优化目标的实际数值贡献 |
| 各关节镜像误差 | 定位单腿或单关节映射问题 |
| actor 原始均值最大值与裁剪比例 | 识别动作饱和掩盖误差 |
| 原始样本 KL 与当前学习率 | 识别更新过强和自适应 LR 变化 |
| estimator 速度误差与 swap loss | 观察估计器是否间接受损 |
| 有效 estimator 样本数 | 识别终止观测配对问题 |
| 镜像系数与规则版本 | 保证结果可追溯 |
| 真实环境步数与更新用样本数 | 区分交互预算和计算预算 |
| update 耗时与峰值显存 | 评价工程成本 |

如果需要观察探索分布的左右差异，应另行统计对应动作维的标准差。当前高斯分布的 `std_type="scalar"` 指直接参数化标准差，每个动作维仍可拥有独立参数，不代表所有关节共享一个相同的标量。[分布实现](../rsl_rl/modules/distribution.py)。

## 十六 常见问题与定位顺序

| 现象 | 优先检查 |
| --- | --- |
| 一开启就出现批次维度不匹配 | estimator 的下一观测和有效掩码是否仍为 `B` |
| KL 计算形状报错 | 新分布参数是否裁到原始 `B` 行 |
| 训练能跑但步态变成错误的左右同步 | 相位是否随左右交换平移半周期 |
| 侧移和转向能力明显下降 | 指令、角速度和关节符号是否正确 |
| 平地正常，粗糙地形变差 | 高度图是否同时错误翻转前后，critic 特权字段是否漏处理 |
| 镜像 loss 很小但原始动作均值极大 | 是否在裁剪后的动作上计算 loss |
| estimator 速度误差突然上升 | 镜像历史是否配到了未镜像的速度目标 |
| 只有 terminal 附近训练异常 | reset 前后监督观测是否混用 |
| 功能关闭也无法续训 | him 与 agent 两个指纹是否都做了窄范围兼容 |
| 功能关闭但固定批次结果改变 | 新增随机数调用、更新次序、张量原地修改或归一化来源 |
| 显存和耗时异常增加 | 是否从已增强数据再次构造镜像，是否重复保存整个 history |
| 对称 loss 降低但任务失败增多 | 权重过大、任务近似对称假设不成立或指标只看均值 |

排查时先确认映射与批次配对，再讨论权重。把映射错误当成超参数问题，会使调参成本很高，也可能让模型学会补偿错误规则而掩盖问题。

## 十七 实施顺序和完成标准

### 第一步固定接口与映射语义

确认 47 维单帧、6 帧历史、244 维 critic、50 维 estimator 的布局；按实际关节和动作顺序建立映射；确定半周期相位规则、扫描坐标置换和动作均值计算方式。

完成标准是形状与物理语义测试通过，所有字段有明确去向，镜像操作不修改原始输入。

### 第二步实现完全关闭的兼容路径

增加显式配置和构造接线，默认 `None`；先处理 dataclass 传递和两个配置指纹。关闭时不初始化机器人映射、不调用额外前向、不新增需要持久化的模型参数。

完成标准是固定批次旧新更新对照通过，旧模型与旧关闭配置的 checkpoint 使用方式保持兼容。

### 第三步接入动作镜像损失

在独立比较批次上计算裁剪前均值，保证两侧 estimator 参数版本一致，保留既有 detached 边界。

完成标准是非对称样例的误差和梯度正确，部署裁剪不变，短程训练没有新的数值异常。

### 第四步接入 PPO 数据增强

按本地 PPO 的语义扩增当前观测、动作及训练目标，KL 和熵仍使用原始样本；estimator 第一阶段继续使用原始监督配对。

完成标准是四种开关组合均通过检查，不重复增强，不改变真实 rollout 时钟和 LP 计数。

### 第五步完成基线对照

在相同真实采样预算和固定评价协议下比较四组核心实验，记录性能、对称性、训练耗时和多个种子的离散程度。

完成标准不是单一 reward 达到某个值，而是能够判断新机制在哪些任务改善、在哪些任务退化，以及额外成本是否值得。

### 第六步研究 estimator 与 critic 扩展

基础接入通过正确性检查、收益或退化来源得到初步定位之后，再加入估计器增强或 critic 对称项，沿用独立开关和消融对照。如果退化来自镜像历史上的估计器误差，应优先验证 estimator 配对增强，再扩大 PPO 增强范围；不要求先证明只有 actor 镜像项就一定获益。

这些扩展若带来收益，应分别记录，避免将一个新的复合算法继续简称为“只给 HIMPPO 加了普通 PPO 的 mirror loss”。

## 十八 面向四足的专项分析与设计

### 18.1 当前四足任务的设计决策

当前对象是 12 关节 RI-4438、带相位的对角小跑、6 帧本体感知历史，以及包含地形信息的非对称 actor critic 结构。这里的“非对称 actor critic”指两者看见的信息不同，与左右不对称是两个概念。

对称机制应帮助策略在互为镜像的情境下复用运动经验，同时保留转弯、单足避障和受扰恢复所需的差异动作。

| 设计项 | 当前决策 | 原因 |
| --- | --- | --- |
| 变换集合 | 原始样本加一个左右镜像 | 左右腿具有对应运动链；映射和误差容易单独核验 |
| 前后及对角交换 | 第一版不加入 | 当前关节轴、限位、默认姿态和任务没有证明这些对称性 |
| 相位 | 当前 trot 使用半周期变换 | 要与四足接触奖励的两组对角腿交换一致 |
| 历史 | 每一帧同步镜像，保持时间次序 | 让关节、动作和 IMU 描述同一段镜像运动 |
| actor loss | 有限权重的均值软约束 | 名义资产及训练环境只近似左右对称 |
| 模型结构 | 保留当前 HIM 与 actor critic | 无需为首次接入更换网络或部署接口 |
| 首轮实验 | 原基线、仅诊断、仅 actor 镜像项 | 先识别映射和表征问题，再扩大优化样本 |
| 后续实验 | PPO 增强与 estimator 增强分别消融 | 两者改变的监督目标和风险不同 |
| 验收目标 | 跟踪、通过性和恢复能力得到保留或改善 | 镜像误差不能单独代表四足控制质量 |

第一版默认仍为 `symmetry_cfg=None`。上述决策不要求改变当前奖励、域随机化、课程公式和部署流程；它规定新增功能开启时如何组织实验。

### 18.2 四条腿之间究竟交换什么

按机身坐标 `x` 向前、`y` 向左、`z` 向上的定义，左右反射是关于 `xz` 平面的反射。只交换左右，保持前后角色。

```text
                     机身前方 +x

               FL   ←────→   FR
               │             │
               │    机身     │
               │             │
               RL   ←────→   RR

            左侧 +y          右侧 -y

对角支撑组 A = FL + RR
对角支撑组 B = FR + RL
左右镜像将 A 与 B 交换，不把前腿变成后腿。
```

为解释规则，假设一个向量按以下**示意顺序**排列：

```text
[FL_hip, FL_thigh, FL_calf,
 FR_hip, FR_thigh, FR_calf,
 RL_hip, RL_thigh, RL_calf,
 RR_hip, RR_thigh, RR_calf]
```

则其镜像结果为：

```text
[-FR_hip, FR_thigh, FR_calf,
 -FL_hip, FL_thigh, FL_calf,
 -RR_hip, RR_thigh, RR_calf,
 -RL_hip, RL_thigh, RL_calf]
```

该列表用于解释物理语义，不能作为运行时固定索引。关节位置、关节速度、动作和足接触各有自己的名称顺序，必须分别解析。尤其不能拿 4 足接触顺序去推断 12 维 actuator 顺序。

左右交换也不是“让左前腿和右前腿在同一时刻输出相同数值”。当前 trot 中它们通常处于不同相位；比较对象是另一段经过完整镜像的输入情境。

### 18.3 为什么第一版不加入前后镜像

四足并不自动意味着可以使用全部腿置换。当前 RI-4438 的左右镜像保持 thigh 和 calf 角度，hip 变号；前后反射关于 `yz` 平面，会产生另一套关节变换。

仅按当前局部关节轴推导，前后反射会要求绕 `y` 的转动方向变化。但 calf 限位为 `[-2.53, -0.84]`，直接取负得到 `[0.84, 2.53]`，已超出当前关节允许范围；默认 thigh 为 `0.9`、calf 为 `-1.8`，也不满足这种简单反射后的默认姿态一致性。[关节轴和限位](../src/assets/robots/ri_4438/xmls/ri_4438.xml)、[默认姿态](../src/config/ri_4438/ri_4438_him_lpacrl_config.py)

这足以否定“把左右镜像模板换一组腿名，就能直接做前后镜像”的做法。它不排除未来通过另一种机构表示或任务设计建立其他映射，但那需要重新证明运动学、可达空间、限位、惯量、动作尺度、奖励和指令的对应关系。

当前 `vx` 正负都参与训练，只表示任务包含前进和后退，并不能证明两者是相同难度的动力学镜像。左右镜像必须保持 `vx` 原符号，保留前进与后退的区别。

因此第一版只使用两元素集合 `{原样, 左右镜像}`。任何增加前后反射或 180 度旋转的设计，都应有独立规则版本和验证结果。

### 18.4 资产核查表明运动学对应成立但动力学并不严格对称

直接检查当前 XML，有以下具体结果：

| 项目 | 当前数据 | 含义 |
| --- | --- | --- |
| 前后 hip 安装点 | `x=±0.14165 m` | 前后安装位置成对，不足以证明前后动力学对称 |
| 左右 hip 安装点 | `y=±0.037 m` | 支持左右几何对应 |
| 左右 thigh 横向偏置 | `y=±0.0834 m` | 与左右腿交换一致 |
| thigh 和 calf 运动链长度 | 分别为 `0.15 m` | 对应足端几何一致 |
| 躯干局部质心 `cy` | `+0.00204115 m` | 名义躯干质心并不位于左右反射平面 |
| 躯干惯量交叉项 | `Ixy=0.00048912`、`Iyz=-0.00003516 kg·m²` | 关于左右平面反射时应变号；原资产不是严格不变 |
| 躯干碰撞盒中心 `y` | `-0.0011 m` | 接触几何也有小幅左右偏移 |
| 左右 thigh 惯性参数 | 局部质心和惯量存在差别 | 不能由质量近似相等推导完整惯性相同 |

依据：[当前资产 XML](../src/assets/robots/ri_4438/xmls/ri_4438.xml)。惯量对比应在相同的 link 坐标系下进行，先将惯性主轴姿态还原成张量，再检验 `I'=R I Rᵀ`；不能直接要求左右 `body_iquat` 四元数相等。

为核验第六章的关节规则，本次对原始 XML 做了只读的 MuJoCo 运动学计算：固定基座姿态，以随机种子 `4438` 生成 128 组四腿独立姿态，hip 在 `[-0.45, 0.45]`、thigh 在 `[0.3, 1.5]`、calf 在 `[-2.3, -1.0]` 内采样，比较对应足端相对机身位置。按“左右交换、hip 取负”映射后，最大坐标误差输出为 `0.000e+00 m`。

这项结果支持当前姿态范围内的足端运动学映射。它没有验证加载地形后的接触求解、执行器延迟、实际 action 索引或闭环训练效果，也不消除表中已存在的动力学差异。

工程结论是采用可调软约束，保留网络补偿真实不对称的自由度。不要为了让等式精确成立，在接入对称训练时顺便修改资产质心或碰撞盒；这会同时改变原任务，失去与旧训练的可比性。

### 18.5 对角小跑相位的完整对应关系

当前四足顺序 `FL, FR, RL, RR` 对应偏移 `β=[0, 0.5, 0.5, 0]`。令 `P=[1, 0, 3, 2]` 表示左右足置换，单足期望接触为：

\[
c_i(\phi)=\mathbf{1}\left[((\phi+\beta_i)\bmod 1)<0.56\right].
\]

所需条件是 `c_i(φ')=c_{P(i)}(φ)`。使用 `φ'=φ+0.5 mod 1` 可以满足这个关系：

| 原相位 | 原期望接触 FL FR RL RR | 镜像相位 | 镜像期望接触 |
| --- | --- | --- | --- |
| `0.10` | `1 0 0 1` | `0.60` | `0 1 1 0` |
| `0.60` | `0 1 1 0` | `0.10` | `1 0 0 1` |
| `0.02` | `1 1 1 1` | `0.52` | `1 1 1 1` |

`threshold=0.56` 大于半周期，因此参考步态包含四足同时支撑的重叠区间。不能把“任意时刻必须恰好两足接触”设成验收条件。当前 `feet_air_time` 在实际半数足接触且符合参考步态时给奖励，这与整个周期都只允许两足接触不同。[奖励实现](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/rewards.py)

本次用 1000 个避开阈值边界的相位样本检查上述关系，期望接触映射全部一致。后续实现仍要检查浮点阈值附近、停止门控和 reset 历史填充。

还要避免把半周期平移作用到整个 `episode_length_buf`。该变量同时关联回合年龄、命令切换和 timeout；镜像应只变换观测中的相位表示，保持同一时刻的训练标签。真正做成对物理轨迹验证时，需要独立处理相位初值，不能通过把回合年龄增加半周期来冒充完整对称。

当前 `step_dt=0.005×4=0.02 s`，周期 `0.6 s` 对应 30 个控制步，半周期是 15 步。6 帧历史相邻间隔为 `0.02 s`，首末帧跨度为 `0.10 s`，既不是完整步态周期，也不包含相隔半周期的两段运动。逐帧把相位的 sin、cos 取负即可，不需要从 rollout 额外取 15 步之后的数据。

### 18.6 将来支持其他四足步态时的规则

半周期变换来自当前偏移表，不是“四足通用公式”。对同样使用单个全局相位、各足采用相同接触函数的设计，一个可检查的条件为：

\[
\delta\equiv\beta_{P(i)}-\beta_i\pmod 1,\quad\text{对全部足 }i\text{ 相同}.
\]

此时取 `φ'=φ+δ`，相位编码按角度 `2πδ` 旋转；当前 `δ=0.5` 才简化成 sin、cos 同时取负。还应检查两次镜像恢复原始输入。

| 参考步态 | 示意偏移 FL FR RL RR | 左右反射下的相位规则 |
| --- | --- | --- |
| 当前 trot 对角小跑 | `[0, 0.5, 0.5, 0]` | `δ=0.5` |
| pace 同侧步态 | `[0, 0.5, 0, 0.5]` | `δ=0.5` |
| bound 前后成组 | `[0, 0, 0.5, 0.5]` | `δ=0` |
| pronk 四足同相 | `[0, 0, 0, 0]` | `δ=0` |
| 不同 walk 或 gallop 定义 | 取决于具体偏移、支撑时长和领步腿 | 逐项求解，可能还要变换步态或领步腿标识 |

这些是偏移模型的示例，不代表当前任务已经支持这些步态。若不同腿使用不同 stance fraction，还必须交换相应参数。若找不到统一 `δ`，不要继续使用旧规则，应明确该步态编码如何镜像，或拒绝为该配置启用增强。

若将来没有显式相位输入，也不能为了复用规则擅自添加两个维度，这会改变旧模型接口。无相位策略可以研究纯空间镜像，但要单独观察从静止启动时能否形成所需的交替步态。

### 18.7 转弯和非对称落脚为什么不应被压制

对于四足，转弯时内外侧腿的足端速度、落脚位置和载荷可以不同。对称项应比较以下两种情境：

```text
原情境指令       vx=0.6   vy= 0.2   wz= 0.4
镜像情境指令     vx=0.6   vy=-0.2   wz=-0.4
```

与此同时交换左右关节状态、接触、历史动作和相位，必要时镜像特权观测。允许“左转时两侧腿不同”，要求的是对应“右转时交换角色”。

单足越障也一样：原情境左前足前方有凸起，镜像情境应把凸起放到右前足前方。不能在保持原地形和原状态不变的情况下强迫两足抬到相同高度。

| 看起来对称但不合适的约束 | 可能损害的四足能力 |
| --- | --- |
| 同一输入下直接最小化左右动作差 | 转弯、交替支撑、独立落脚 |
| 前腿和后腿始终使用相同轨迹 | 上下台阶时的承重和探步差别 |
| 四足接触力始终相等 | 转弯、受推、斜坡和动态支撑 |
| 同一块单侧障碍地形上要求两侧行为相同 | 单足越障和地形适应 |
| 镜像历史仍复用原始 latent | 与历史不符的隐式环境表征 |

因此不建议新增“左右腿动作相等”的环境奖励，也不在部署时平均两侧动作。当前方案只在训练中比较正确成对的输入及输出。

### 18.8 当前奖励与终止条件的四足审查

分析奖励的对称性，应先看完整物理状态和必要的历史是否一起变换，再看标量形式是否保留。仅把 critic 向量反射一遍，并不能证明环境奖励的全部输入都覆盖了。

| 当前项目 | 在理想左右镜像下保持的条件 | 应重点检查 |
| --- | --- | --- |
| 水平与偏航速度跟踪 | 实际速度与指令同步变换，平方误差保持 | `vy` 与 `wz` 都要变号，`vx` 不变 |
| 机身姿态、角速度、角动量惩罚 | 正确反射向量后相关平方范数保持 | 角速度、角动量属于轴向量 |
| 关节力矩、加速度、动作变化惩罚 | 相关关节和全部时间片同步置换变号 | 当前动作与历史动作不能使用不同索引 |
| `pose` 与 `hip_pos` | 默认姿态、按关节权重及命令门控对应 | 地形容差来自扫描，不能只镜像关节 |
| `foot_gait` | 左右足交换，并变换相位 | 原实际接触与参考接触都要匹配 |
| `feet_air_time` | 同步交换接触时间、离地时间和参考相位 | 隐藏的计时器不能只靠 4 位 contact 推断 |
| `foot_slip` | 对应足的接触和水平足速同步镜像 | 足 site 与 contact sensor 顺序一致 |
| `soft_landing`、`stumble` | 接触力和触地事件同步镜像 | first contact 依赖时间状态 |
| 碰撞和跌倒终止 | 对应碰撞几何、姿态和力满足映射 | 现有名义碰撞盒偏移导致近似而非严格对称 |
| timeout 与地形边界截断 | 保留回合年龄，并正确映射地图及边界 | 不能只改相位时钟或只改机身朝向 |

当前源码中虽然定义了 `feet_clearance()`，但本任务默认 `rewards` 字典没有注册它；不能把它写成当前已启用的抬脚奖励。若以后启用，该函数的相位、足端路径、地形高度和接触力都应纳入核验。[实际奖励配置](../src/tasks/locomotion/ri_4438_him_lpacrl/ri_4438_him_lpacrl_env_cfg.py)、[奖励函数](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/rewards.py)

上述审查支持用可控的镜像状态检查奖励各项；它不是对当前资产的奖励和转移严格不变的证明。PPO 增强仍沿用第三章的近似训练语义。

### 18.9 域随机化需要区分同一个机器人和机器人分布

若某次随机化让左前腿的增益偏小，镜像情境对应右前腿增益偏小。原环境实例本身可以不对称；可利用的对称性来自成对的参数设置及其采样分布。

设环境隐参数为 `η`，更完整的假设是：

\[
\eta'=M_\eta(\eta),\qquad
P_{\eta'}(M_s(s')\mid M_s(s),M_a(a))
\sim P_\eta(s'\mid s,a).
\]

要让随机化任务分布也保持对称，还需要 `η` 与 `Mη(η)` 的采样概率对应。独立同分布的左右参数有助于这一点，但“每个范围都写成正负对称”不足以证明完整分布成立。

| 当前随机化 | 镜像时的语义 | 对设计的影响 |
| --- | --- | --- |
| 四足共享摩擦系数 | 标量保持 | 不必假设当前默认存在逐足摩擦差异 |
| 四足共享接触时间常数 | 标量保持 | 当前四足共享一次采样 |
| PD 增益、effort limit、关节摩擦等 | 左右对应关节交换，标量不取负 | 同一个实例不要求对应参数恰好相等 |
| 编码器偏置 | 对应关节交换，按角度映射变号 | 直接变换已有历史，不另抽一份偏置 |
| 躯干质心和惯量 | 质心用 `R`，惯量用 `R I Rᵀ` | 只镜像 critic 的 COM 不等于物理模型已变换 |
| IMU 安装误差与 gyro bias | 与传感器坐标和轴向量规则一致 | 保留同一段镜像历史的误差关系 |
| 外力和速度冲击 | 按其实际坐标系反射 | 世界坐标的力不能直接套机身坐标的某一维符号 |
| 观测和执行器延迟 | 对应历史通道和待执行动作队列一起映射 | 不倒转时间，不重新采样延迟 |

这些取值及共享规则见[事件配置](../src/tasks/locomotion/ri_4438_him_lpacrl/ri_4438_him_lpacrl_env_cfg.py)和[任务随机化实现](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/domain_randomization.py)。

当前 COM 随机化是在已有名义惯性参数上施加扰动。即使 `com_displacement_range=[-0.05, 0.05]`，也不能据此忽略名义 `cy`、惯量交叉项和腿部惯性差异，并宣称当前整个动力学分布精确左右对称。

第一版增强只构造训练张量，不去改写正在采样的环境参数。这是一种任务分布近似；遇到固定单侧载荷、损坏执行器或单侧限制，应通过专门对照判断是否继续采用该先验，而不是简单增大镜像系数。

### 18.10 粗糙地形与扫描镜像的边界

当前高度扫描是跟随机身 yaw 对齐的局部网格。镜像表示同一机身朝向坐标下，左侧和右侧高度信息交换；它不表示把楼梯高度取负，也不表示将上楼换成下楼。

| 原场景 | 对应镜像场景 | 保持的内容 |
| --- | --- | --- |
| 左侧局部凸起 | 右侧同高度凸起 | 高度数值与前后位置 |
| 向前爬升台阶 | 向前爬升的镜像台阶 | 上下方向及 `vx` |
| 左高右低的横坡 | 右高左低的横坡 | 坡度大小 |
| 斜着接近台阶 | 反射后的接近角度与台阶几何 | 相对碰撞与落脚关系 |

当前地形按类别、等级和副本生成，`replicas=1`，并使用固定种子。`random_rough` 的某一张有限高度图一般不等于它自己的左右反射；生成器在统计上具有某种对称性，也不意味着当前这张图包含全部镜像轨迹。[固定地形生成](../src/tasks/locomotion/ri_4438_him_lpacrl/mdp/terrains.py)

对称增强不会创建新的地形碰撞模型。critic 的 187 点扫描镜像只补充了局部训练信息，不能被当作在镜像地图上重新执行动作、获得相同 return 的实测证据。

此外，当前 actor 只使用本体感知和历史，没有读取高度图。critic 看见地形不代表部署 actor 拥有同样信息。盲视四足主要依赖接触后身体与关节响应调整动作；对称训练不会自动获得提前感知障碍的能力。

建议把平地映射核验、原任务粗糙地形评价，以及独立的镜像地图诊断分开。正式 LP 评价继续使用原有地图和协议，镜像诊断不得回填原课程回报。

### 18.11 HIM 的历史表征是四足设计的重点

同样的当前姿态，可以对应“左腿打滑后刚恢复”和“右腿打滑后刚恢复”两段不同历史；它们需要的后续动作未必相同。只镜像最新一帧、保留前五帧不变，会制造不属于同一段镜像运动的输入。

完整镜像历史应满足：

\[
M_h(h_t)=\left[M_o(o_{t-5}),\ldots,M_o(o_t)\right],
\qquad
(\hat v',z')=E(M_h(h_t)).
\]

这里 `z'` 由估计器重新推断。可以检查显式速度是否接近 `(v̂x, -v̂y, v̂z)`，但不对未知语义的 latent 维度手工变号，也不把 `z'=z` 当作正确答案。

当前 estimator 输出在 actor 路径中停止梯度。因此，actor 镜像 loss 无法直接教 estimator 处理镜像历史。如果估计器在原始历史上预测正常、在镜像历史上预测偏差很大，actor 可能被迫补偿不可靠的输入表征。此时仅提高 actor 镜像系数并不能解决监督配对问题。

建议增加以下诊断，在固定观测集上独立计算，不改变默认训练更新：

| 诊断 | 解释 |
| --- | --- |
| 原始历史的速度监督误差 | 估计器基线能力 |
| 镜像历史与镜像真实速度的监督误差 | 镜像分支是否存在明显表征退化 |
| `E_v(M_h(h))` 与 `R E_v(h)` 的差 | 显式速度预测的一致性，不代替真实监督误差 |
| 两种历史下的动作镜像误差 | actor 与 estimator 合成后的策略一致性 |
| 按 reset 后时间和地形分组的误差 | 历史不足、接触扰动和任务切换的影响 |

若镜像分支的 estimator 误差是主要问题，可以独立测试“原始与镜像历史、下一观测同步增强”的方案。保留 estimator 自己的优化器和原损失，不以对称功能为由取消 detached 边界。

6 帧历史提供短时信息，但不保证能识别持续偏载、执行器退化或长期滑移。第十二章 SGMA 的结果提示需要关注上下文；它使用 RNN，不证明当前有限历史已经足够，也不构成本次改成 RNN 的理由。

### 18.12 四足映射应作为任务适配器

HIMPPO 可以共享更新逻辑，机器人映射应由任务提供。不要在 `rsl_rl/algorithms/him_ppo.py` 内写死 `FL`、187 个扫描点或第 9、10 维相位。

拟议任务适配器应在启用时建立以下只读描述：

| 描述 | 由哪里确定 | 必须满足 |
| --- | --- | --- |
| 机器人与映射版本 | RI-4438 任务配置 | 启用配置可追溯，不能冒用其他机器人规则 |
| 观测字段布局 | observation group 的实际拼接结果 | 每个字段有语义，宽度和历史轴一致 |
| 关节置换与符号 | 各观测 term 的实际名称和轴 | 一一对应，两次镜像恢复 |
| 动作置换与符号 | action term 实际 actuator 顺序 | 与目标关节、默认 offset 和 scale 相容 |
| 足接触置换 | contact sensor 的实际足顺序 | 与步态、足端 site 对应 |
| 步态相位规则 | period、offset、stance threshold | 满足期望接触对应，不静默套错步态 |
| 扫描置换 | 实际射线局部坐标和对齐方式 | 左右配对存在，缺失射线明确报错 |
| estimator 布局 | 独立监督观测组 | 先变换完整观测，再提取监督切片 |

运行时缓存 index 和 sign 张量即可，避免在每个 mini-batch 重复用字符串匹配。`symmetry_cfg=None` 时不解析这些信息；启用时遇到不支持的布局应尽早报出具体字段，不截断或填零后继续训练。

RI-4438、Go2 或其他四足即使都为 12 自由度，也不能仅凭维数相同共享同一个硬编码数组。关节轴、符号、排列、站姿和相位约定都可能不同。可共享构造工具，每个任务仍需独立验证。

### 18.13 损失尺度要考虑四足动作单位

当前基础 `action_scale=0.5`，hip 还乘 `hip_reduction=0.5`，因此 hip 的位置目标尺度为 `0.25 rad/动作单位`，thigh 和 calf 为 `0.5 rad/动作单位`。

本地 PPO 的 mean MSE 在归一化动作空间比较误差。同样 `0.1` 动作误差，对 hip 对应约 `0.025 rad`，对 thigh 或 calf 对应约 `0.05 rad`，这里指进入关节限位裁剪前的位置目标差。相同的动作 MSE 并不意味着各关节具有相同的角度、力矩或能耗误差。

为了对齐本地 PPO，第一版保持原始均值的普通 MSE，不悄悄增加按力矩或角度重加权的目标。同时记录：

- hip、thigh、calf 各自的动作镜像误差。
- 使用 action scale 转换后的关节目标角度差。
- 四腿分别的输出裁剪、关节限位接近情况和力矩饱和比例。
- 任务跟踪误差、足端滑移和落地冲击。

若后续选择按角度差加权，应作为不同 loss 定义单独命名和比较。降低动作镜像 MSE 本身不证明能耗降低；需要实际计算关节功率或其他能耗指标。

### 18.14 四足专用验证与实验矩阵

在第十四、十五章的一般检查上，补充以下四足条件：

| 层级 | 检查内容 | 判据 |
| --- | --- | --- |
| 映射 | 四腿各自独立的非零关节姿态、足接触标记和动作标记 | 对应足端位置正确，索引不串腿 |
| 步态 | trot 全周期、四足支撑区间、零命令、启动与停止 | 接触参考随左右交换对应，不强迫始终两足支撑 |
| 时间 | 6 帧内容各不相同，命令切换出现在历史中间 | 各帧独立镜像，时间与切换位置不变 |
| 奖励 | 成对状态下逐项检查 reward，不只看总和 | 理想对应条件下差异符合容差；实际资产偏差单独记录 |
| 估计器 | 原始及镜像的速度监督、terminal 有效掩码 | 不使用错误的下一观测，不掩盖无效样本 |
| 开启更新 | loss、增强、estimator 增强分别验证 | 梯度路径、目标标签和批次大小清晰 |
| 部署 | 单路确定性推理、原输入输出与裁剪 | 无额外镜像融合或网络结构依赖 |

闭环评估建议覆盖以下场景。前三类可先做短程诊断，完整结论仍依赖正式训练及多种子对照。

| 场景 | 需要观察的四足行为 | 比较方法 |
| --- | --- | --- |
| 平地直行及后退 | 两组对角腿交替、侧向漂移、机身 roll | 分别评价正负 `vx`，左右镜像不合并前后成绩 |
| 正负侧移 | 左右步幅、滑移、跟踪误差 | 相同速度大小成对比较 |
| 正负原地转向及弧线 | 内外侧腿差异、偏航误差、限位 | 保留内外侧合理差异，不以同刻动作相等评分 |
| 原配置楼梯与粗糙地形 | 前后腿过阶、单足碰撞、拖足和失败率 | 按地形类别、等级和方向分组 |
| 双侧方向的外力与偏载 | 恢复时间、身体倾斜、补偿动作 | 使用对应成对扰动；也保留原随机化分布测试 |
| 起步、停止及箱内命令切换 | 步态过渡、历史信息不足、短时饱和 | 将过渡窗口与稳态统计分开 |
| 单侧障碍与横坡 | 独立落脚和适应能力 | 原场景及其镜像地图分别执行 |

标准 `evaluation` 模式会移除训练随机化、噪声和延迟。因此原 LP 评估只能回答其名义条件下的任务表现，不能单独证明偏载和扰动鲁棒性。上述鲁棒性场景应在独立评估配置中执行，避免改动 LP 的试验表和历史分数。[模式处理](../src/tasks/locomotion/ri_4438_him_lpacrl/config/env_cfgs.py)

建议额外记录四足接触序列、各足占空比、步频、摆动高度、滑移距离、接触冲量及各腿关节功率。直行的左右统计可以按相位对齐比较；转弯和非对称地形则比较互为镜像的两次试验，不要求单次试验内四腿统计相等。

所有新增指标都是拟议诊断，不代表现有 evaluator 已经提供。

### 18.15 成对物理诊断应如何构造

“把 `vy`、`wz` 取负再跑一次”适合做方向能力对照，但严格的镜像物理试验还要对应地形、初始状态、扰动和模型参数。

以绕某个固定世界竖直平面反射为例，选平面上的原点 `p0`，反射矩阵 `S=diag(1,-1,1)`。世界位置使用 `p'=p0+S(p-p0)`；若机身姿态矩阵为 `Q`，可使用 `Q'=S Q S`，保持结果为合法旋转，并同时应用对应腿和关节映射。线速度及外力使用普通向量反射，角速度及力矩使用轴向量反射。不要将四元数的某一维随意取负来替代该推导。

需要同步处理的状态还包括动作延迟队列、接触计时、观测历史及传感器误差。地形与边界也围绕同一平面反射；若该地形实例不是自身对称，必须准备对应地图。

名义 RI-4438 本身有小幅不对称，可以做两类不同目的的诊断：

1. **映射和动力学诊断**：在独立诊断环境中使用配对的模型参数、地形和历史状态，检查变换误差。当前相位与回合年龄耦合，应独立处理相位初值；不能宣称现有 reset 直接生成严格成对轨迹。
2. **真实任务性能诊断**：始终使用实际 RI-4438 资产，比较左右方向的通过性和恢复表现，接受物理不对称造成的差别。该结果决定软约束是否过强。

两者不可混为一项。“同一种子”只保证随机序列的可重复性，不会自动把噪声、外力或地形变成镜像；如需耦合采样，应先生成原始扰动，再显式构造对应扰动。

### 18.16 对当前 LPACRL 的具体实验安排

默认 600 个任务包含 `5 个 |vx| 档 × 6 个 |wz| 档 × 5 类地形 × 4 档等级`，方向在箱内采样。默认每个任务 8 个评估 trial，并不意味着左右方向在每个任务中都严格均分；每个 trial 中命令还会切换。

因此不要只用一个任务平均回报判断左右一致性。可在保留原评估分数的同时，增加按实际命令片段分类的 `vy>0`、`vy<0`、`wz>0`、`wz<0` 统计，并报告样本数量、持续时间及命令幅度范围。接近零的命令单独分组；样本量少的方向差不能解释为稳定收益。

独立方向诊断可预先生成一组完整命令序列，再对每个片段应用 `(vx,vy,wz)→(vx,-vy,-wz)`，同时明确地图和初态是否镜像。这样能区分“箱内随机抽样恰好不平衡”与“策略真实偏向某侧”。

建议按以下顺序推进，避免一次开启全部扩展后无法定位收益：

| 阶段 | 实验范围 | 决定下一步的证据 |
| --- | --- | --- |
| Q0 | 旧策略的离线镜像诊断和原任务评价 | 现有策略在哪些腿、方向和地形有偏差 |
| Q1 | 实现支持但完全关闭；再运行仅诊断路径 | 关闭回归通过，诊断不改变训练结果 |
| Q2 | 原基线与仅 actor 镜像项，保持原 estimator 更新 | 方向差改善且跟踪、地形能力未明显退化 |
| Q3 | 仅 PPO 增强、仅镜像项、两者组合与基线 | 分离增强与一致性约束的贡献 |
| Q4 | 如有表征退化，单独加入 estimator 配对增强 | 镜像速度监督改善，并反映到任务表现 |
| Q5 | 在固定采样和正常 LP 下比较，补充鲁棒性评价 | 确认算法收益与课程反馈的各自影响 |

如果 Q2 就发现镜像历史的 estimator 误差突出，可以先进入 Q4 的小规模诊断，再进行 Q3。阶段编号表示实验组织，不要求忽略已发现的问题按表机械推进。

critic 显式对称项继续作为更后面的独立扩展。对当前非严格对称资产、固定地形和不完全对称的有限历史策略，不能一开始就把两侧 value 必须相等当作额外硬要求。

### 18.17 决定是否保留机制的标准

对当前四足项目，保留该机制的理由应该来自以下联合结果：正确性检查通过；关闭时兼容；开启后在固定预算下，方向一致性、任务表现或样本效率有可重复改善；粗糙地形、转弯和受扰恢复没有不可接受的退化；计算成本有记录。

如果只有离线镜像 MSE 更低，机器人却出现步幅缩小、拖足、上下阶困难、转向迟钝或抗扰变差，就不应仅凭“更对称”判定成功。应依次检查映射、相位、历史配对、估计器误差，再判断软约束强度和任务近似对称是否适用。

当前设计的重点是让四足策略在对应情境下学会交换角色，同时保留对具体接触和环境条件作出不同动作的能力。

## 十九 普通 HIM 去掉显式步态和相位的设计

### 19.1 分析范围与结论

本章仅分析 `src/tasks/locomotion/ri_4438_him` 和 `src/config/ri_4438/ri_4438_him_config.py` 对应的普通 RI-4438 HIM，不使用 LPACRL 的任务分箱、学习进展评价或采样公式作为论据。

普通 HIM 在没有显式 gait 奖励、没有观测相位的情况下，仍有机会学出稳定、协调的四足步态。对称机制可以帮助降低无必要的左右偏好，但它既不是无相位运动的必要条件，也不是学出指定步态的充分条件。

需要区分两个目标：

| 目标 | 对无显式相位方案的判断 |
| --- | --- |
| 跟踪指令、保持稳定，并根据速度和地形形成合适运动节奏 | 值得建立独立基线，再评估对称机制的增益 |
| 在给定频率下持续输出指定的对角小跑和接触顺序 | 单靠对称机制不能保证，仍可能需要相应先验 |

当前普通 HIM 自身也有环境课程设置。这里“不分析 LPACRL”不意味着必须删掉普通任务已有的地形或命令课程；对照实验应固定这些设置，让比较集中于显式步态与对称机制。

### 19.2 原版 HIM 的直接依据

官方 HIMLoco 提交 `ef289acaa62795009363b7b819c9186690630441` 的基础 actor 观测由指令、角速度、重力投影、相对关节位置、关节速度和上一动作组成，没有周期相位。基础配置采用 45 维单帧和 6 帧历史。该版本 Go1 的奖励配置还将 `feet_air_time` 权重设为零。[官方观测实现](https://github.com/InternRobotics/HIMLoco/blob/ef289acaa62795009363b7b819c9186690630441/legged_gym/legged_gym/envs/base/legged_robot.py#L244)、[基础配置](https://github.com/InternRobotics/HIMLoco/blob/ef289acaa62795009363b7b819c9186690630441/legged_gym/legged_gym/envs/base/legged_robot_config.py#L35)、[Go1 奖励配置](https://github.com/InternRobotics/HIMLoco/blob/ef289acaa62795009363b7b819c9186690630441/legged_gym/legged_gym/envs/go1/go1_config.py#L87)

这支持 HIM 无需显式相位输入即可开展四足运动学习。它没有证明把 RI-4438 的相位直接删除就会得到同样结果，也没有证明这种能力来自额外的对称损失。机器人动力学、观测顺序、奖励和仿真环境都仍有差别。

原版的命令字段位于单帧开头；本项目命令位于 `[6:9]`。即使去掉相位后都为 45 维，也不能直接复制原版的固定切片或模型权重。

### 19.3 三种机制分别提供什么

| 机制 | 当前作用 | 没有直接规定的内容 |
| --- | --- | --- |
| 相位观测 | 提供周期内的显式时间位置 | 单独提供时钟不必然指定足接触顺序 |
| 当前 `foot_gait` 奖励 | 按周期和偏移表指定各足的期望接触 | 不直接给出完整的关节轨迹 |
| 对称损失 | 鼓励镜像输入产生对应的镜像动作均值 | 步频、步幅、抬脚高度和具体步态类型 |
| 对称数据增强 | 用镜像训练样本补充相应情境 | 不会产生新的真实交互或自动设计步态 |

去掉 gait 和相位，相当于减少对运动时间结构的显式规定；加入对称机制，相当于约束不同空间情境之间的决策关系。这两个方向可以组合，但不存在“加一个对称 loss 就自动代替全部步态设计”的等价关系。

例如，一个始终输出零动作的策略也可以具有零镜像误差；稳定站立、左右同步跳动以及某些交替步态，都可能符合一定的左右对应关系。因此需要速度跟踪、稳定性和运动成本等目标来区分这些行为的任务价值。

对称策略也不要求每个时刻的身体姿态或每一条实际运动轨迹都左右对称。策略可以在不同支撑状态下产生不同动作，镜像约束比较的是对应状态之间的输出。

### 19.4 没有时钟时如何形成运动节奏

关节状态本身包含运动阶段的信息。例如，同一个关节角度既可能出现在向前摆动时，也可能出现在向后支撑时，但两种情况下的关节速度、上一动作和近期机身响应不同。

当前 HIM 的输入与估计器可以利用：

- 当前关节位置和速度，区分腿的空间位置与运动方向。
- 上一动作及各历史帧，区分近期控制和响应。
- IMU、重力投影及速度估计，判断身体运动和稳定性。
- 从历史提取的 latent，为部分不可直接观测的环境响应提供信息。

反馈策略与机器人动力学相互作用后，可以形成周期运动，不一定需要外部时钟逐步告诉网络何时摆腿。历史也不必覆盖完整步态周期才能提供有用的运动阶段信息。

这不等于 estimator 一定学出了一个可解释的相位变量。当前模型是处理固定历史窗口的前馈网络，不是具有无限记忆的 RNN；相似历史仍可能对应不同接触条件，历史不足的限制依然存在。

当前 actor 没有直接读取 critic 中的四足接触和地形扫描。因此不应把“critic 能看到足接触”写成“部署策略已直接获得足接触相位”；部署时仍要依靠自己的观测和历史响应。

### 19.5 当前普通 HIM 的相位依赖不能只删一处

普通 HIM 中，`foot_gait` 使用周期 `0.6 s`、偏移 `[0, 0.5, 0.5, 0]` 和接触阈值 `0.56`，其当前奖励权重为 `0.5`。`feet_air_time` 权重为 `1.0`，但它也读取前者的配置，并要求实际接触符合参考步态。[普通 HIM 奖励配置](../src/tasks/locomotion/ri_4438_him/ri_4438_him_env_cfg.py)、[奖励函数](../src/tasks/locomotion/ri_4438_him/mdp/rewards.py)

| 依赖位置 | 当前行为 | 无显式步态实验需要处理的内容 |
| --- | --- | --- |
| actor 的 `phase` term | 输入相位 sin、cos | 删除显式相位输入 |
| critic 的 `phase` term | 同样包含相位 | 本方案同步删除，保持无时钟定义清晰 |
| `foot_gait` | 奖励按时钟匹配参考接触 | 无步态组关闭该项 |
| 当前 `feet_air_time` | 读取周期、阈值、相位与指定支撑组 | 同步关闭，或另行设计不依赖这些字段的奖励 |
| `config/env_cfgs.py` | 直接读取并同步 gait、air time 和相位配置 | 移除或条件化相关绑定，不能留悬空引用 |
| `ESTIMATOR_TERMS` | 明确列有 `phase` | 从独立监督观测组同步移除 |
| estimator 目标切片 | 仍按 47 维单帧定位 | 按新布局调整，不能只修改维度声明 |
| 动作观测数值边界 | 固定使用 `[35:47]` | 按新动作字段位置调整 |

只将 `foot_gait.weight` 置零而保留当前 `feet_air_time`，仍然在奖励指定的相位及支撑组。直接删除 `foot_gait` 字典项又保留其他引用，则可能在环境组装或奖励计算时失败。

只删除相位观测、继续按不可见时钟奖励指定接触，也没有实现自主形成步态。它让策略更难辨别奖励要求，并使不变换时钟的纯空间镜像可能对应错误的接触标签。

源码中定义的 `feet_clearance()` 也读取 gait 参数，但当前普通 HIM 的默认奖励字典未注册该项。应审查将来启用它时的依赖，不能把函数存在与当前参与训练混为一谈。

具体入口：[环境绑定](../src/tasks/locomotion/ri_4438_him/config/env_cfgs.py)、[estimator 观测组](../src/tasks/locomotion/ri_4438_him/mdp/terminal_observations.py)、[数值契约](../src/config/ri_4438/numerics.py)。

### 19.6 无相位后的镜像规则

在上述相位和奖励依赖全部处理后，左右镜像只需要变换具有明确空间含义的字段：

1. 保留 `vx`，将 `vy`、`wz` 指令取负。
2. 按普通向量与轴向量规则变换重力、线速度和角速度。
3. 交换左右腿，按当前关节轴处理关节位置、速度和动作的符号。
4. 对全部历史帧执行相同的空间映射，保持时间顺序。
5. 将镜像后的完整历史重新送入 estimator，得到对应的速度和 latent。
6. 数据增强涉及 critic 或监督目标时，同步变换其接触、质心、扫描和下一观测字段。

不再执行显式半周期相位平移，不循环移动历史帧，也不需要去找真实轨迹中半周期之后的样本。

前文第六章、第十八章的半周期规则针对带显式 trot 时钟的任务。无相位组应使用另一份有清晰布局标识的映射描述，不能对新的 `[9:11]` 再做 sin、cos 取负，因为该位置已经属于关节位置。

### 19.7 输入布局与旧模型兼容

以下是拟议的真正删除相位方案：actor、critic 和 estimator 监督观测组均移除两个相位维度，其余字段及 6 帧历史保持原定义。

| 项目 | 当前普通 HIM | 拟议无相位 HIM |
| --- | --- | --- |
| actor 单帧 | `47` | `45` |
| actor 6 帧历史 | `282` | `270` |
| critic 单帧 | `244` | `242` |
| 独立 estimator 监督观测 | `50` | `48` |
| estimator 目标网络输入 | `47` | `45` |
| actor 动作网络输入 | `47+3+16=66` | `45+3+16=64` |
| 动作输出 | `12` | `12` |
| `history_term_dims` | `(3,3,3,2,12,12,12)` | `(3,3,3,12,12,12)` |
| 动作观测切片 | `(35,47)` | `(33,45)` |
| 速度监督切片 | `(47,50)` | `(45,48)` |
| estimator 目标切片 | `((0,6),(9,47),(47,50))` | `((0,6),(9,45),(45,48))` |

其中 estimator 目标宽度为 `6+36+3=45`，继续排除命令 `[6:9]`，保留显式速度监督。该表由当前普通 HIM 的字段顺序推导，不代表运行时配置已经修改。[普通 HIM 中央配置](../src/config/ri_4438/ri_4438_him_config.py)、[RL 适配](../src/tasks/locomotion/ri_4438_him/config/rl_cfg.py)

拟议 actor 单帧新布局如下：

| 切片 | 字段 |
| --- | --- |
| `[0:3]` | 机身角速度 |
| `[3:6]` | 重力投影 |
| `[6:9]` | 指令 |
| `[9:21]` | 相对关节位置 |
| `[21:33]` | 相对关节速度 |
| `[33:45]` | 上一动作 |

拟议 critic 在其后依次追加 `[45:48]` 线速度、`[48:51]` COM、`[51:55]` 四足接触和 `[55:242]` 高度扫描。必须从实际 observation manager 再核对布局，并更新相应镜像、归一化和部署描述。

网络首层权重、estimator 编码器与目标网络输入、归一化统计都会受维度变化影响。旧 47 维 checkpoint 不能直接当作 45 维模型完整续训；首轮科学对照宜从头训练各组。若将来裁剪权重列或迁移统计，应定义为独立迁移方案，不能称为无影响续训。

保留 47 维但把相位恒置零，是另一种屏蔽输入实验：它可以保留部分张量形状，但旧策略面对的输入分布已经变化，也仍需处理全部奖励依赖。它不能替代真正的 45 维布局定义。

普通任务的数值契约位于 `src/config/ri_4438/numerics.py`。未来实现需检查共享使用方，避免为无相位变体修改一个全局切片，却影响仍使用 47 维输入的任务。

### 19.8 奖励与启动探索的设计边界

去掉显式步态后，仍可以保留速度跟踪、机身稳定、关节限制、动作平滑、力矩、足端滑移、碰撞和停止命令下的姿态等基础目标。它们决定运动质量，但不直接规定固定相位偏移表。

删除原来权重为正的 gait 和 air time 奖励，会改变优化目标的相对平衡。即使其余系数完全不变，策略也可能更倾向于减少关节运动。若出现小步挪动或拖足，应先检查奖励贡献、动作幅度和滑移，而不是只提高对称系数。

可以另行研究不依赖全局相位的接触事件、摆动质量或适度离地时间奖励，但这属于额外设计。例如按触地事件评价已完成的摆动，不要求某条腿在外部时钟的指定时刻落地。此类奖励仍可能偏好某种步长或节奏，需要独立记录；不应把新奖励悄悄混入无步态基线。

无相位还需要关注启动时的探索。在理想的严格对称系统中，如果完整输入历史满足 `M_h(h)=h`，严格等变的确定性策略会给出满足 `M_a(a)=a` 的动作。它缺少主动选择某一侧先迈步的区别信号，可能停留在左右同步的运动状态。

当前拟议的是有限权重的软约束，训练还有随机动作、噪声与实际不对称，因此不意味着一定无法起步。但过强的镜像项可能抑制形成交替运动所需的早期差异。应观察静止启动、低速、停止后再启动，以及确定性部署时的行为。

初期保留原探索机制和有限镜像权重，避免同时进行动作强制平均、严格参数对称化和大幅降低探索噪声。若需要权重渐增，作为单独配置和消融记录，不能默认它一定优于固定系数。

### 19.9 四组普通 HIM 对照实验

第一轮将“对称机制”具体限定为动作均值镜像损失，保持 estimator 原始监督更新；后续再单独研究数据增强和 estimator 配对增强，避免同名实验包含不同算法。

| 实验 | 显式 gait 与相位 | 动作镜像损失 | 用途 |
| --- | --- | --- | --- |
| A | 保留当前设置 | 关闭 | 当前普通 HIM 基线 |
| B | 保留当前设置 | 开启 | 测量有步态先验时的对称增益 |
| C | 去除全部相关依赖 | 关闭 | 无显式步态 HIM 基线 |
| D | 与 C 相同 | 开启 | 测量无显式步态时的对称增益 |

这里的“去除”包括当前与 gait 耦合的 `feet_air_time`。若采用新的无相位奖励，C 和 D 必须同时采用，且应与没有该新奖励的版本区分。

| 对比 | 可以回答的问题 |
| --- | --- |
| A 与 C | 删除当前整套显式步态设计后，普通 HIM 表现如何变化 |
| C 与 D | 无显式步态时，动作镜像项是否带来实际增益 |
| A 与 B | 保留当前时钟和接触约束时，对称机制能否改善表现 |
| B 与 D | 同样使用对称机制时，两种步态设计各有什么优劣 |

A 与 C 同时改变观测和奖励，因此不能单独归因于“少了两个输入维度”。若将来需要区分时钟信息与奖励的作用，应另设更细的消融，但不能以删除观测、保留不可见相位奖励作为默认自由步态方案。

对照中保持机器人资产、基础奖励、隐藏层规模、仿真控制周期、真实采样预算、历史长度、域随机化、命令范围和普通任务已有课程一致。相位删除必然改变输入层参数数量，需如实记录，不强求四组网络总参数完全相等。

正式比较使用相同的种子集合和独立评价条件。至少 3 个训练种子可用于初步比较，同时展示离散程度；单次训练的视频或最高回报不足以证明稳定优势。

数据增强的后续消融可以在 C 的无相位定义下增加“仅增强”和“增强加镜像项”两组，并明确原始环境步数与墙钟时间。若镜像历史的 estimator 误差明显增大，先诊断监督配对与表征，再扩大增强范围。

### 19.10 什么才算学出了不错的步态

评价不能只看动作镜像 MSE，也不能直接比较 A 与 C 的训练总 reward：两组已使用不同奖励项，总分标尺发生变化。应使用共同定义的物理指标和固定评价场景。

| 维度 | 建议指标或观察 |
| --- | --- |
| 指令能力 | `vx`、`vy`、`wz` 误差，正负方向分别统计 |
| 稳定性 | 跌倒率、存活时间、机身 roll 和 pitch、扰动恢复 |
| 足端运动 | 四足接触序列、步频、占空比、滑移、拖足与碰撞 |
| 步态协调 | 对角腿与同侧腿的配合、步间波动、起停过渡 |
| 动作成本 | 力矩、关节功率、动作变化及饱和比例 |
| 地形能力 | 平地、楼梯、粗糙地形的通过性和失败模式 |
| 对称性 | 固定观测集的镜像误差，以及成对方向试验的性能差 |
| 训练成本 | 达到同一物理表现所需环境步数、时间及显存 |

“没有显式相位”不是禁止测量步频或事后分析接触相位。可以从实际触地事件重建运动周期用于评价，只要不把该分析偷偷反馈为训练中的固定时钟约束。

直行可以按实际周期对齐左右行为；转弯、单侧障碍和扰动恢复则允许一次试验内两侧动作不同，应比较互为镜像的情境。若自主策略采用不同于固定 trot 的协调方式，应先按任务表现评价；若指定 trot 是必须条件，则将接触顺序单独列为目标。

支持采用 D 的证据应包括：相对 C 有可重复收益，且相对当前 A 在关键任务上没有不可接受的退化。如果只是镜像误差更低，却变成左右同步跳动、小步拖行、启动迟缓或越障退化，就不能判定步态更好。

普通 HIM 加无显式相位再加左右对称软约束，是一个有依据、值得验证的设计方向。先建立 C，才能判断 D 的改进来自对称训练；当前分析不构成已在 RI-4438 上验证成功的结论。
