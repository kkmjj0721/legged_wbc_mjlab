# 本地四足机器人迁移工作台

工作台将一个标准 12 关节四足机器人接入本项目的训练、回放和导出流程。支持 RI-4438 的 PPO、HIM、HIM Symmetry、HIM LP-ACRL 模板，每种任务生成独立实现。

![本地 URDF Studio 姿态预览](assets/robot_migration_workbench/pose_workspace_ri5036.png)

上图为第 04 步的大画布工作区，使用 RI-5036 展示模型、内置工具栏、姿态控制和足端标记。

## 安装与启动

首次安装环境时启用 Web 依赖：

```bash
bash setup.sh --extra web
```

已有可用训练环境时，可以只同步可选依赖并保留当前 PyTorch 后端：

```bash
python3 tools/uv_auto_sync.py --extra web --skip-torch -- --no-install-package torch
```

在项目根目录启动：

```bash
uv run --no-sync python -m scripts.robot_migration_web --port 5003
```

打开 <http://127.0.0.1:5003>。服务只绑定本机；页面、本地 URDF Studio 预览、字体和视频均使用同一服务，不需要 CDN。停止终端服务会同时释放预览与验证进程。已有服务需重启并刷新页面才能加载更新。

## 迁移步骤

流程按四组划分，每次只编辑当前步骤。第 01–11 步点击“确认本步并继续”后自动保存草稿与确认摘要；也可以通过左侧导航回看。

| 分组 | 步骤 | 本步确认内容 |
| --- | --- | --- |
| 模型与任务 | 01 导入模型 | XML / URDF、资源依赖、转换报告和网格面数预算 |
| 模型与任务 | 02 选择任务 | PPO、HIM、Symmetry、LP-ACRL 与 Flat / Rough |
| 模型与任务 | 03 机器人映射 | 名称、机体、12 个关节顺序、镜像符号、足端和碰撞 |
| 机器人与控制 | 04 初始姿态 | 机体位置/朝向、关节角、3D 模型与足端位置 |
| 机器人与控制 | 05 电机与动作 | 限矩、armature、被动阻尼/摩擦、动作缩放/裁剪、硬件补充与 T–N 曲线 |
| 机器人与控制 | 06 时序与环境 | 仿真步长、控制降采样、执行器与观测延迟、环境数、求解器 |
| 机器人与控制 | 07 PD 增益 | 核对输入 → 运行搜索 → 比较结果 → 应用与确认；或填写已有增益 |
| 任务与训练 | 08 指令与地形 | 速度范围、地形、课程和 LP-ACRL 任务参数 |
| 任务与训练 | 09 随机化与观测 | Reset、动力学扰动、观测噪声；延迟统一放在第 06 步 |
| 任务与训练 | 10 奖励权重 | 只调整权重，其余函数参数可展开只读查看 |
| 任务与训练 | 11 训练参数 | 训练预算、保存间隔、网络、PPO 与 estimator |
| 审阅与生成 | 12 审阅文件 | 任务 ID、目录树、源码、配置差异与人工确认 |
| 审阅与生成 | 13 生成与验证 | 暂存、CPU 检查、写入、清理、可选短仿真与命令 |

导入可以直接填写完整文件路径、目录与相对入口，或上传 ZIP；内置 RI-4438 / Go2 示例可直接选择。只给文件路径时自动确定资源目录；只给目录时选择唯一入口，ZIP 多入口需指定。LP-ACRL 保留各课程预设，自动识别的映射和站姿仍需核对。

配置步骤共用“公共配置 / 各算法覆盖”页签，确认摘要检查所有选中任务的有效值。修改参数不会删除其他步骤的数据；与该参数有关的已确认步骤会标为“待复核”，右侧可以展开查看上次确认摘要。修改奖励或训练预算不要求重测 PD；改变站姿、惯量、限矩、动作或控制时序会使相关 PD 结果过期。恢复原值可以恢复原确认状态。恢复默认和关节批量赋值只作用于当前步骤。

保存、恢复草稿保留当前步骤及确认记录；旧草稿仍可读取，需要逐步确认后生成。恢复草稿后，历史 PD 报告可查看，再次应用需重新测试。审阅前必须完成 11 项配置确认；纯导航、查看摘要不使文件预览失效，实际配置或报告变化仍需重新审阅。进度元数据只保存在草稿中，生成文件以实际模型和配置为准。

生成使用新目录，已有同名目标拒绝覆盖；失败时回滚本次写入。完成后提供训练、零动作回放命令和可选 CPU / GPU 检查。

目录标识只填写机器人名，例如 `ri_5036`，无需附加 `_him`。第 03 步随名称和算法选择实时显示源码目录及训练输出位置；第 12 步按实际生成清单审阅。只选 HIM 时生成 `src/config/ri_5036/ri_5036_him_config.py` 一个算法配置，另保留运行适配、观测布局等必要公共文件；不复制 PPO 或其他未选算法配置。机器人目录为 `src/assets/robots/ri_5036/`，任务目录为 `src/tasks/locomotion/ri_5036_him/`。机器人包仅包含运行 XML 实际引用的网格等资源与工厂，不带转换用原始 URDF/STL 副本或转换报告。原始导入资料仍在工作目录中。

训练命令的日志/模型路径明确显示为 `logs/rsl_rl/ri_5036_him/<timestamp>[_<run_name>]/`。时间戳在启动训练时确定，默认无运行名后缀；添加 `--agent.run-name trial` 后目录以 `_trial` 结尾。页面不启动正式训练。


无模型 keyframe 时，初始关节角采用模板站姿作为起点，并限制在模型运动范围内；这不是从硬件测得的站姿。PD 必须手工填写或显式应用候选，未填写时禁止生成，不继承 RI-4438 增益。延迟、armature 和随机化等模板参数仍需按新机器人确认。执行器延迟以物理仿真步计，观测延迟以控制步计。

参数索引覆盖控制、电机、模型预算、时序、环境、指令、重置、随机化、噪声、地形、课程、奖励和训练项，并区分可编辑配置与只读契约。`environment.mujoco` 可调整积分器、求解器、摩擦锥、Jacobian、重力、迭代次数、容差及支持的标志；只接受当前 MuJoCo-Warp 支持的组合（例如求解器为 Newton / CG，sleep 要求 Newton）。奖励区仅开放权重，函数和其他参数按各任务模板保留并只读展示。新机器人后续可能需要专门调整奖励参数，第一版不自动推断这些值。

新模型的接触和约束数量可能不同于 RI-4438。迁移预设将 `environment.nconmax` 和 `environment.njmax` 分别设为至少 256 和 1500，可在环境配置中调整；这些是缓冲区容量，不是已标定的机器人参数。

3D 预览采用用户指定的 [URDF Studio](https://urdf.enkeebot.com/) 的实际开源 RobotCanvas，在本地打包运行；XML / URDF 均展示最终导入的 MJCF。第 04 步默认展开大画布工作区，桌面端将画布、全部 12 个关节和确认按钮放在同一屏；可返回常规布局或进入浏览器全屏。画布按屏幕像素比高清渲染（DPR 1.75–2.5），内置旋转/平移模式、缩放、适应/复位、前/侧/顶视，以及外观/碰撞、坐标、关节轴、质心、惯量和足端标记开关。窄屏按纵向排列。关节滑块和根位姿由主页面编辑，足端位置与姿态以 MuJoCo CPU 前向运动学为依据。它不验证稳定站立，也不包含线上编辑器的 AI 或云端功能。日常运行不需要 Node.js；固定上游版本、构建和许可见 [预览组件说明](../web_ui/studio/README.md)。

步骤 01 的“模型资源预算”统一作用于所有任务。`model.mesh_face_limit` 限制每个生成 mesh 的三角面数，默认取 `max(200000, 当前最大网格面数)`，可以修改并随草稿和生成清单保存。低于实际面数时仍可预览和保存草稿，审阅/生成会要求调整预算；修改预算不改变网格或进行减面。URDF 导入的运行网格统一使用 OBJ，完整三角几何保留，不再受 STL 解码器面数上限影响。

## 地形参数怎么填

第 08 步中，普通 PPO / HIM / HIM Symmetry 的通用地形生成参数按下表填写；LP-ACRL 的自定义地图/嵌套等级配置保持其独立含义。

| 字段 | 含义与填写 |
| --- | --- |
| 生成难度区间 `difficulty_range` | 仅两个有限端点“最小难度, 最大难度”，下限不大于上限，例如 `0, 1`；通常在 0–1 区间内使用。不是 `0,1,2,3,4,5` 这样的等级列表；不将超出 0–1 自动截断或认定为依赖强制禁止 |
| 地形行数 `num_rows` | 正整数。按行课程开启时，每行一个难度等级；6 行对应等级索引 0–5，10 行对应 0–9，实际难度在两个端点之间线性分布 |
| 地形列数 `num_cols` | 正整数。随机生成模式使用这个值；按行课程开启时，实际每种子地形占一列，生成器忽略此数值 |
| 按行生成难度课程 `curriculum` | 控制生成器的地形排列/分配模式；开启时按行增加难度，不是独立设置初始地形等级上限 |
| 单地块尺寸 `size` | 两个正数，单位 m，例如 `8, 8` 表示每块地形 8m × 8m，不是整张地图总尺寸 |
| 整图外围平地宽度 `border_width` | 非负数，单位 m。`20` 表示整图外围的平地边宽20m，不是地形等级或地块数量 |

例如希望按行生成 0–5 共6个等级，可设置 `num_rows=6`、`difficulty_range=[0,1]`；各行的难度参数为0、0.2、0.4、0.6、0.8、1。生成器允许相同端点表示固定难度。前端会在错误列表长度/顺序/尺寸上提示并阻止确认，后端API也独立校验；旧草稿中的非法值会保留并提示，不静默取前两个数字或替用户改训练参数。平地任务没有使用地形生成器时，这些网格参数不生效。

普通模板会列出各个子地形的权重和详细尺寸：上/下楼梯的阶高区间、踏面深度、中央平台、内部平地边宽与孔洞，随机高低方块的宽度、高度区间和合并参数等。每类可单独展开，修改会实际用于生成任务的训练及回放配置。课程模式每类占一列；权重仍影响出生比例，不能把权重直接理解为课程地图面积占比。

“查看地图布局”显示实际行列、单地块/整图尺寸和类型分配；“计算实际全局 geom”按当前配置和分析种子 42 在 CPU 构建完整地图，给出机器人、地形、全局 geom、mesh 和 heightfield 数量。全局 geom 是共享地图加一个机器人模型的 `MjModel.ngeom`，含纯视觉几何，不乘并行环境数量，也不是三角面或接触点数量。超过 1024 地块、估算 50000 geom 或 4000000 高度场采样时不执行同步构建，明确显示预算限制，不缩小或改写配置。分析种子不修改训练种子；参数变化后结果标为待重算。

## 电机参数怎么填

步骤 05 统一填写**电机转子惯量 + 关节总传动比**，关节侧 armature 自动计算且只读。总比默认 `N=1`（1:1 直驱），有减速时改为总传动比；修改后 PD 分析、响应测试、预览和生成的训练配置自动使用相同结果，无需先应用 PD 候选。扭矩与转速仍以最终关节输出轴为准，不随 N 自动改值。

| 字段 | 应填写的数值 | 实际用途 |
| --- | --- | --- |
| 仿真扭矩上限 `effort_limit` | 实机控制器实际允许的关节扭矩上限，可采用受驱动器、电流、传动与机械限制后的峰值或降额值；若只允许持续额定扭矩则填该值 | 训练与 PD 响应的固定扭矩限幅；填峰值时也没有峰值持续时间或热降额模型 |
| 关节等效驱动惯量 `armature` | 只读：由裸转子惯量与总传动比自动计算；不是连杆刚体惯量 | `J_arm = J_rotor × N²`，PD 与训练配置共用 |
| 电机转子惯量 `J_rotor` 与总传动比 `N` | 直接填裸电机转子轴惯量，单位 kg·m²；N 默认 1，定义为 `abs(转子转速 / 关节转速)` | 自动替换该关节的等效驱动惯量，不累加；原始输入保存到草稿和生成清单 |
| 额定连续扭矩 `continuous_torque` | 相应散热、温度等工况下关节侧可持续输出的额定值，不能填短时峰值 | 只作高级静态比例项预算比较；不替换仿真限矩，不作为自动搜索的持续负载或温升验收 |
| 允许最高工作转速 `velocity_limit` | 当前电压、驱动器、机械共同允许的关节最高工作速度，单位 rad/s；不是额定工作点转速，不能直接把空载极限视为带载能力 | PD 响应按峰值速度判超速，不钳速、不生成训练限速；未知留空 |

**直驱**指转子直接带动关节，没有减速：填 `N=1`，`J_arm=J_rotor`，电机与关节的扭矩/转速数值相同。若电机输出经过额外减速，N 包含转子到关节之间的全部传动；内部 6:1、外部 2:1 时，总 `N=12`。电机数据换算为 `τ_joint ≈ η × N × τ_motor`、`ω_joint = ω_motor / N`，η 是传动效率；扭矩与转速须自行换算，填写 N 只触发惯量折算。惯量公式不乘效率。[MuJoCo armature 定义](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-joint-armature)、[Oriental Motor 传动关系](https://www.orientalmotor.com.sg/sg/tech/reference/gear-head06)

例如裸转子 `J_rotor=0.0001 kg·m²`，直驱的 armature 为 `0.0001`，加 3:1 减速后为 `0.0009`。若电机额定扭矩为 2 N·m、峰值 6 N·m、允许最高工作转速 600 rpm，以理想效率 η=1 举例，3:1 后关节额定 6 N·m、峰值 18 N·m、最高工作转速 200 rpm ≈ 20.94 rad/s；实际扭矩须按效率和控制/传动限制修正。换算 `rad/s = rpm × 2π / 60`。算例不代表任何机器人的标定值。

额定转速描述额定工作点，允许极限速度另有定义；额定扭矩的持续能力也有工况条件，填写时核对厂家参数口径。[Kollmorgen 电机参数定义](https://www.kollmorgen.com/en-us/developer-network/motordaten-legende-0)

转子惯量未知时留空，仍保留原配置或模型中的关节惯量，并标明它只是原有假设；不会把未知当 0，也不会把已经折算的 armature 反当成裸转子惯量。惯量无峰值/额定之分；厂家给 g·cm² 时乘 `10⁻⁷` 转为 kg·m²。多级传动件自身的旋转惯量需另外建模，`J_rotor × N²` 不会自动包含它们，模型已包含的同一惯量不要重复计入。

公共配置的转子惯量和传动比由各任务继承，任务页签可以逐字段覆盖（例如只覆盖减速比）。原始输入保存在 `spec.motor_inertia.scopes`；生成清单另存有效折算值与来源。旧草稿补充区的 J/N 会兼容迁移；只有旧 armature 的草稿保留原值并显示转子未知。恢复默认只作用当前步骤/作用范围。

额定能力补充表的转速可选择 **rpm / rad/s**，默认 rpm；切换只改变显示和输入单位，后台仍以 rad/s 保存与比较，不改变已有数值、PD 报告或步骤确认。单位偏好随草稿保存，旧草稿中的速度仍按原 rad/s 数据正确换算展示。

补充表上方可以选择 hip / thigh / calf，输入一次转速或额定连续扭矩后点击“应用到四条腿”，只更新当前页签中四个同类关节。顶部原有关节批量栏也支持这两项；转子惯量、传动比等仍可在那里批量设置。转速单位在表头与两个批量栏同步，切换时会换算尚未应用的速度值；扭矩输入始终为 N·m。批量转速与连续扭矩都须为正数，非法输入不写入配置。

动作缩放只在第 05 步的“动作缩放”卡片中设置：`action_scale` 为基础缩放（rad），`hip_reduction` 为髋关节乘数。默认 0.5 和 0.5 时，hip 的最终缩放为 0.25 rad，thigh/calf 为 0.5 rad；最终目标角为初始角加策略动作乘最终缩放，再应用目标角限位。PD 与训练都只乘一次 hip 系数。逐关节基础缩放在高级折叠表里覆盖，旁边显示最终结果；统一设置基础缩放会替换当前作用范围内的逐关节值。旧草稿的映射保持原数值，例如 hip 基础值已经填 0.25 且系数为 0.5 时，最终结果为 0.125 rad。

## PD 参数分析

步骤 07 将 PD 整定分为四个阶段：

1. **核对输入**：先看模型、站姿、电机与时序摘要，需要时展开逐关节来源，或返回第 04–06 步修改，然后确认本次测试输入。
2. **运行搜索**：开始 CPU 测试，查看状态、停止操作和折叠日志。无需先填写自然频率、阻尼比或 PD。
3. **比较结果**：默认先显示所选候选的通过数、到位和过冲摘要；全部候选和逐关节响应按需展开，视频可直接播放。
4. **应用与确认**：单独查看 Kp/Kd/armature 写入前后值，点击应用；再在页面底部确认本步。也可以从“填写已有 PD”直接进入手动输入，不强制运行搜索。

未配置时，仅在测试副本中使用 **Kp=20.0、Kd=0.5** 作为对照，表单和生成配置仍为空；部分缺失时仅对缺失项补入这个测试基准。工具搜索 3 / 5 / 8 Hz、阻尼比 0.7 / 1 / 1.3 组成的九组模型惯量候选，测试基准不参与推荐或应用。已完整填写 PD 时，以测试时的配置作对照。这些只是有限搜索范围，不代表硬件推荐值。

自动测试仍然需要输入，只是大部分已由导入模型和当前配置提供。测试按钮前的“本次测试使用的输入”显示逐关节实际使用的 armature、限矩、被动阻尼、摩擦、初始角及来源，以及仿真步长与执行器延迟。修改参数、补充电机数据或切换任务页签后，摘要随之更新；数据来源不代表已经实机标定。

- **模型刚体惯量**：各连杆的质量、质心和惯量从编译后的 URDF/MJCF 读取，不要求在页面重复填写；应核对原模型的惯性参数，网格外形本身不能证明质量分布准确。
- **电机折算惯量**：`armature` 是自动折算的额外驱动惯量，URDF 连杆的 `inertial` 通常不包含这项传动折算。填写裸转子惯量与关节总传动比（默认 1:1），系统自动计算，且与生成训练配置一致。转子惯量未知时继续使用当前模型/配置假设，不从扭矩、转速反算；例如模板的 `0.008234 kg·m²` 不能当作新机器人的已知值。[MuJoCo 惯性与 armature 定义](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-joint-armature)
- **执行器与工况**：核对关节端的仿真力矩上限、初始姿态、摩擦、被动阻尼和延迟。连续力矩与最大转速可补充，未知时保持未知；可按下文确认 T–N 数值包络，没有热模型。自然频率、阻尼比无需事先知道，由候选库扫描。

测试在独立 CPU 子进程中串行运行，可查看日志和停止。以当前站姿固定机身与其他关节，关闭重力和接触，逐关节运行正负小幅阶跃；报告展示到位时间、过冲、末端误差、力矩饱和比例和响应曲线。仿真使用配置中的力矩限幅、armature、被动阻尼、摩擦及执行器目标延迟，并同步所选积分器、求解器、迭代数、容差和标志；报告分别记录请求与实际选项，明确实验对重力和接触的覆盖。实机更新频率和实测延迟输入仅作记录，不冒充已经建模的硬件控制器。

测试完成后页面提供两段 MP4：测试对照与推荐候选；无推荐时用得分最好的扫描候选作失败对照。视频回放真实测试轨迹，依次展示 hip / thigh / calf，每段约 6 秒、640×480、25 fps，可直接播放和下载。这是固定机身、其余关节锁定且无重力/接触的响应实验，不是整机站立或训练步态。视频渲染失败会单独提示，不将数值测试冒充已成功录制。报告与日志保留供追溯；视频只在生成前供比较，任务生成成功后自动删除，不归档到源码目录。

固定种子 42，每个方向 2 秒、最多 0.05 rad，按动作目标限位裁剪；不足 0.005 rad 的方向跳过并提示，两侧均不足则拒绝测试。通过条件为数值有效、进入并维持 2% 误差带至结束且至少 0.1 秒、过冲 ≤20%、饱和时间占比 ≤10%，并检查已填写的速度上限。误差带至少为 0.0001 rad；这些是本工具的筛选条件，不是行业验收标准。位置执行器与积分方式见 [MuJoCo 动力学说明](https://mujoco.readthedocs.io/en/stable/computation/index.html)。

结果中的频率和阻尼比是候选设计目标，响应指标来自仿真轨迹；工具不会将它们标为实机辨识值。推荐只比较本次有限候选与工况；没有全部关节通过筛选的候选时，页面明确显示无推荐。选择候选、检查逐关节 KP / KD / armature 的变化后，点击应用才会写入当前配置页签。测试本身不修改 PD；相关测试输入改变或恢复草稿后，需要重新测试才能应用。切换页签会保留各自报告，搜索中的结果按请求作用范围归档，修改奖励、训练预算或环境数不会丢弃结果。整机站立、行走、其他姿态及实机响应仍需分别验证。

上图使用 RI-4438 演示参数输入和计算结果，示例中的硬件补充值仅用于界面验收，不是实机标定数据。

手动分析复用当前模型、站姿、逐关节动作缩放、髋关节动作系数、目标角范围、力矩上限和执行器惯量。先选择公共配置或某个任务页签，再填写自然频率、阻尼比、姿态采样幅度与用于预算检查的动作幅度。初始的 5 Hz、阻尼比 1 是可修改的设计假设，不是依据实机标定得到的推荐值；自然频率也不等于电机实测带宽。

可补充实机底层 PD 更新频率、反馈到执行的延迟、连续扭矩和速度上限。电机转子惯量与关节总传动比已统一到第 05 步主表；N 默认 1，`J_arm = J_rotor × N²` 自动用于 PD 与训练，armature 不再单独手填。转子未知时沿用原配置/XML 假设并标注。

工具提供两组候选：

- **模型负载惯量法**：在当前站姿及各关节类型的正负偏移姿态计算 MuJoCo 质量矩阵，取逐关节 `M[i,i]` 的采样最大值作为设计惯量。它表示基座及其他自由度锁定、无接触约束时的惯量，包含当前配置的 `armature`，不重复相加。结果显示采样最小值、当前姿态值、最大值及候选响应范围；有限姿态采样不能覆盖整个工作空间。
- **电机惯量基线**：仅用电机折算惯量计算增益，供参考项目公式对照；未计入连杆负载。某关节惯量为零时该方法不可用，可继续使用模型法或补齐执行器参数。

两法使用 `Kp = J × (2πf)²`。模型法的 `Kd = max(0, 2ζJ × 2πf − b)` 中，`b` 是配置或 XML 的被动黏性阻尼，发生截零时会提示实际阻尼比与目标不同；电机基线沿用 `Kd = 2ζJ_arm × 2πf`。报告会说明单关节近似、重力/接触、离散控制和饱和的适用边界。

增益分组可选择自动、逐关节或左右成对。自动模式在 HIM Symmetry 页签，或公共配置包含 Symmetry 任务时，对前腿和后腿的左右镜像关节分别共用候选增益。模型法采用配对的最大采样惯量，并取两侧所需阻尼增益的最大值；各关节实际惯量和预计响应仍分别显示。这是满足当前对称训练契约的工程选择，不是论文声称的通用最优整定。原有 armature、被动阻尼、限矩或动作缩放若不满足镜像要求，只提示差异，不替用户修改这些物理输入。

力矩预算按照当前零目标速度、零前馈的位置控制语义计算。在默认关节角、零速度下，检查正负指定动作幅度经实际动作缩放和目标角限幅后的比例项力矩，并与配置限矩及已填连续力矩比较。`Kp × 实际动作缩放` 是单位动作变化对应的比例项力矩增量，不是机器人运行时的力矩上界。动作幅度是本次检查输入，不会更改策略的原始动作裁剪。

比较两法和当前参数后，选择候选并检查应用前后差异，再应用到当前页签。仅填入候选 KP、KD 与计算所用的 armature；动作缩放、力矩上限及其他任务覆盖保持原有值。公共配置仍会被各任务自己的覆盖值覆盖，应在对应页签重新计算和检查。更改配置或分析输入后，旧结果不能继续应用；恢复草稿后也需要重新计算。

分析输入、报告和应用记录随草稿保存，并包含在生成清单 `migration_manifest.json` 的 `spec.pd_analysis` 中；也可下载 JSON 报告单独审阅。这些是设计与估计记录，不是实机标定证明。连续力矩、速度和实机时序补充输入用于分析，不改写训练时序；当前生成任务仍使用内建位置执行器及配置的固定限矩。支撑接触、反馈滤波、真实延迟、减速器摩擦、柔性和热限制需要后续仿真或实测验证。

方法参考：[BeyondMimic 附录 S1](https://arxiv.org/html/2508.08241v4)、[MjLab 执行器说明](https://mujocolab.github.io/mjlab/main/source/actuators.html)、[Modern Robotics 关节力矩控制](https://modernrobotics.northwestern.edu/nu-gm-book-resource/11-4-motion-control-with-torque-or-force-inputs-part-1-of-3/)。仿真与实机响应对齐参考 [Tan 等，2018](https://arxiv.org/html/1804.10332) 和 [Hwangbo 等，2019](https://arxiv.org/html/1901.08652)。

## 电压 T–N 曲线

在步骤 05 上传厂家在指定电压下的 PNG / JPEG / WebP（最多 20 MiB），记录型号、电压和关联关节。图片仅作为参考资料，工具不自动 OCR 或从图片猜测限矩。需要让曲线参与 PD 测试时，手动取点填写 `rpm, N·m`，确认电压、输出轴和数值后勾选启用；修改这些数据会取消确认。

- **关节输出端**：直接使用关节端力矩/转速，不额外填写减速比。
- **电机 / 模组输出端**：以厂家曲线所标输出轴为准，只填写该轴到关节之间的额外减速比；直接连接为 1。若曲线已包含内部减速，不重复计算。这里的额外比与裸转子表的总 N 各自填写，不自动联动。
- 曲线从 0 rpm 的正力矩开始，到零力矩的最高转速结束；转速递增、力矩不增。同一关节只能启用一条曲线，不混用连续与峰值数据。这个零扭矩端点是包络边界，与允许最高工作转速分开填写。峰值只适合对应短时工况，当前包络不模拟其持续时间，连续力矩另行记录。

PD 响应测试每个物理步按实际速度插值，并取曲线限矩与固定限矩的较小值。当前是速度绝对值上的对称包络，不包含四象限制动、温升或电池压降。**T–N 包络目前只用于受控 PD 测试，生成的训练执行器仍使用固定限矩**；生成配置的 `motor_curves/index.json` 明确记录这一点，并归档图片与确认数据，关闭 Web 后仍可审阅。

## URDF 转换

例如模型目录如下，可以只在任一输入框粘贴完整路径 `.../my_robot/urdf/my_robot.urdf`；也可以将目录填为 `.../my_robot`，入口填为 `urdf/my_robot.urdf`，或上传包含这些文件的 ZIP：

```text
my_robot/
  urdf/my_robot.urdf
  meshes/...
  textures/...
```

转换后的 XML 参考 Go2 与 RI-4438 的组织方式：两空格缩进，依次组织 `compiler`、`default`、`asset`、`worldbody` 与 `sensor`；每个 body 显式列出惯量、关节、视觉和碰撞对象，再嵌套子 body。视觉和碰撞使用独立 class / group，资源使用包内相对路径。生成机器人 XML 与资源可以独立使用。

生成任务会按足端碰撞类型适配接触 margin：网格或 box 足端使用 `0`，其余足端使用模板的 `0.001 m`，以满足当前 Warp MULTICCD 的要求。此适配记录在生成绑定中，原 XML 几何保持不变。

保留源 URDF 的 link / joint 名称、固定连接层级、坐标变换、关节轴和限位、质量、质心、完整惯量、mesh scale、颜色及碰撞几何。惯量原点的旋转转换到 body 坐标系，不自动修正非法惯量。无质量根节点与固定连接的有质量机身会分别识别，质量随机化绑定有质量机身，腿部惯量随机化排除无质量辅助节点；固定足端子节点也会用于足端绑定。

URDF 的 `limit.effort` 读入逐关节力矩上限，`dynamics` 阻尼和摩擦保留在 XML。PD、执行器延迟、动作缩放等仍需配置，`limit.velocity` 仅记录在转换报告中，不自动变成速度控制器。初始基座位置从原点开始，请设置离地高度并检查站姿。IMU 与足端 site 是依据命名和几何生成的候选，页面会提示人工确认；ROS/Gazebo 控制器和插件不迁移。

资源支持相对路径、绝对路径和 `package://` 引用，转换输出统一改成相对路径。本地文件导入会结合 URDF 引用确定资源公共目录，只复制实际依赖；ZIP 资源始终限制在解压目录内，不接受越界或符号链接。所有运行网格统一为 OBJ：二进制 STL 保留原始 float32 三角坐标、顺序及绕序；ASCII STL、PLY/OFF 和可用的 DAE 直接解码为 OBJ，以 17 位有效数字写入，不经过二进制 STL。已有 OBJ 原字节复用，保留其 UV 与法线；其他格式保留可用 UV，材质/颜色使用 URDF 定义。同一资源和缩放下的视觉与碰撞共用资产，不拆分碰撞凸包或简化。原始资源仍归档，报告记录编码与实际面数。碰撞 mesh 按 MuJoCo 的凸包语义参与接触，凹形需要人工提供代理。DAE 仍需可用的可选解析器，缺少时提示先导出 OBJ，本功能不新增安装依赖。格式与凸包语义见 [MuJoCo mesh 文档](https://mujoco.readthedocs.io/en/stable/XMLreference.html#asset-mesh)。

统一 OBJ 策略作用于新导入的 URDF。已有导入快照、原 MJCF 模型和源目录保持原样；对旧模型应用此策略时，重新导入原 URDF 即可。box / sphere / cylinder 等解析几何仍保留原定义。

两个输入框填写不同的完整模型文件路径时会拒绝导入，避免旧入口覆盖新选择；使用完整文件路径时另一个输入框可以留空。遇到不支持的 mimic 时，提示包含实际读取文件、机器人名称、关节数量与联动关系，便于区分标准四足与带机械臂/夹爪的模型；不通过删除 mimic 标签忽略机构约束。当前已知 RI-5036 的原 URDF 为 12 revolute + 4 fixed、无 mimic，可正常导入。

导入副本及最终生成的机器人目录中包含 `conversion_report.json`、转换后的 XML / assets，以及 `source/` 下原 URDF 与实际使用的原资源。报告记录源文件摘要、资源、保留项、补充定义和警告；源文件中的 URI 保持原文，运行使用转换后的 XML。恢复草稿或重新导入转换包会保留该来源记录。

## 数据和验证结果

- `.artifacts/robot-migration/imports/`：导入资源的本地副本与解析记录，源模型保持原样。
- `.artifacts/robot-migration/drafts/`：版本化 JSON 草稿；保留导入资源才能恢复其预览和生成能力。
- `.artifacts/robot-migration/motor-curves/`：上传图片和来源信息。
- `.artifacts/robot-migration/jobs/`：验证日志、结果、视频与生成事务清单。
- 正式训练输出仍由现有入口写入 `logs/rsl_rl/`。

每次验证结束或停止后自动清理该作业的临时目录和编译缓存；正式生成成功后，还删除暂存树、关联模型的已完成 PD 作业视频和重复请求/CPU 检查文件。其他模型和仍在运行的作业不参与清理。页面显示数量和保留项，当前草稿会移除失效视频链接；原始模型、导入工作副本、草稿、图片、报告、日志和最终任务继续保留；失败时保留诊断证据。

CPU 检查包含注册、原任务配置摘要、模型编译、对象映射、实际执行器参数、初始状态、配置隔离和 HIM 布局。Symmetry 还检查左右配对、镜像符号、初始姿态和几何关系。

GPU 短仿真固定种子 42、4 个环境、200 个控制步，使用零动作检查运行、观测和奖励有限性。任务串行运行，可停止；GPU 不可用时显示“未运行”。页面不启动正式训练。

第一版接受独立浮动机器人 MJCF，或由 fixed / revolute 树组成的 URDF；最终要求 12 个具有有限运动范围的旋转关节，以及可明确绑定的足端和碰撞对象。URDF 的 mimic、continuous、prismatic、闭链和未展开 xacro 会给出错误提示。MJCF 场景入口、外部插件、绝对资源路径和对象名称中的 `/` 不接受。HIM 观测布局固定为 `phase47_v1`；非对称运动学需要选择兼容模板或先修正映射。

短仿真与短训仅验证相关链路，不证明策略已收敛或适合实机。开发验收的具体命令和结果见 [开发记录](development.md)。
