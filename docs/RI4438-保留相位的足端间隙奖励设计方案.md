## 1. 当前基线与本次修改范围

本方案对应本轮分析时的工作区配置：

| 项目 | 当前值 |
| --- | --- |
| 相位周期 | `0.6 s` |
| 四脚相位偏置 | `[0.0, 0.5, 0.5, 0.0]` |
| 支撑相位阈值 | `0.56` |

当前 clearance 在预期摆动相位内，用正弦曲线规定每个时刻的最低脚高。即使实际迈步高度相同，只要抬脚时间相对时钟发生偏移，也可能增加惩罚。

第一轮实验只替换 `foot_clearance` 的实现，沿用其 `-0.25` 权重。保留相位观测和 `foot_gait=0.25`，其余奖励、地形课程和训练参数沿用对照组配置，以便判断这一项修改的效果。

## 2. 一次完整迈步如何确认

每只脚独立经历以下过程：

> 确认支撑 → 实际离地 → 记录间隙峰值 → 确认落地 → 更新成绩和计时。

一次迈步的结算不读取相位。确认条件如下：

1. 先观察到稳定支撑，才能开始记录迈步。出生时悬空、随后落地不直接获得一次合格成绩。
2. 实际无接触至少 `0.04 s`，防止单帧接触抖动被算成迈步。
3. 只用实际无接触且高度有效的样本记录间隙。
4. 返回支撑后，连续确认 `0.04 s` 才结算。
5. 触碰台阶立面不直接结算，也不清空待完成的迈步记录。允许继续调整并再次离地，最终在形成支撑时结算。

“完成迈步”与“高度合格”分开判断。低抬脚也会得到一次结算，但成绩较差；不能因为落了地就把高度惩罚清零。

### 支撑确认的第一版近似

使用现有 `feet_ground_contact` 和 `feet_terrain_height`，同时满足：

```python
support = (
    (found > 0)
    & (abs(force_z) > 1.0)
    & (norm(force_xy) <= 5.0 * abs(force_z))
    & isfinite(height)
    & (height >= 0.0)
    & (height <= 0.04)
)
```

这里的接触力使用世界坐标系分量。当前接触传感器的 `netforce` 聚合提供世界系合力。

该条件能排除一部分明显的立面碰撞，但它是近似判据：摩擦力、台阶边缘以及脚同时接触多个面都可能造成误判。验证时需要记录被判为支撑的接触样本，不能把合力方向当成精确的接触面法向。

### 峰值如何记录

高度继续使用 foot site 相对脚下地形的距离，不使用世界坐标 z。

为避免单帧射线高度尖峰获得高分，使用相邻两个有效离地样本的较小值，再累计最大值：

```python
sustained_height = min(height_t, height_previous)
peak = max(peak, sustained_height)
```

两帧必须都实际离地且高度有效。遇到接触或无效高度，清除用于配对的上一帧样本；已经获得的本次迈步峰值保留到确认落地。

这项过滤只能抑制孤立尖峰。脚跨过台阶边缘时，脚下地面高度真正改变仍会影响间隙值；这个峰值不等同于脚相对起点的净向上位移。

## 3. 奖励公式

每只脚保存：

- `last_deficit`：上一次已完成迈步的高度不足程度，范围 `[0, 1]`。
- `age`：距离上一次已完成迈步的时间。
- `peak`：当前尚未完成迈步的间隙峰值。
- 接触确认、有效离地标记及上一帧高度等辅助状态。

### 3.1 落地时更新高度成绩

```python
last_deficit = clamp(
    (target_height - peak) / (target_height - rest_height),
    0.0, 1.0,
) ** 2

age = 0.0
```

建议初值：

```python
target_height = 0.10
rest_height = 0.01573
```

`target_height=0.10 m` 是 foot site 到地面的距离。按当前脚部几何的参考高度 `0.01573 m`，对应约 `8.4 cm` 的净抬升，而不是额外抬高 `10 cm`。更换足部几何后需要重新检查 `rest_height`。

平方缺口用于减轻小幅不足的代价。内存原型曾试过线性缺口：在该模型的平地轨迹上，持续扣分导致平均惩罚约为旧项的 2.4 倍，因此最终建议采用平方形式。

每次完成迈步都替换成绩，包括低质量迈步，不能永久保留历史最好成绩。

### 3.2 每个控制步计算超时程度

移动指令有效时递增 `age`，本步若确认落地，再将对应脚的 `age` 归零：

```python
late = clamp((age - step_window) / late_ramp, 0.0, 1.0)
cost = last_deficit + (1.0 - last_deficit) * late
```

建议：`step_window=1.0 s`，`late_ramp=0.4 s`。

| 情况 | 评分行为 |
| --- | --- |
| 上一步高度合格，下一步在 1 秒内完成 | 没有高度不足或超时惩罚 |
| 上一步抬得不足 | 保留相应惩罚，直到下一次结算更新成绩 |
| 距离上一次结算超过 1 秒 | 逐渐增加超时惩罚 |
| 达到 1.4 秒仍未完成下一步 | 该脚达到满额惩罚 |
| 不断低幅轻点地 | 即使刷新计时，低质量成绩仍然受罚 |
| 长期悬空或一直着地 | 没有新的完整迈步，最终达到满额惩罚 |

计时从各脚自己的实际落地事件开始，不按 `phase % period` 划分。正常每 `0.6 s` 迈一步，越障时延长到 `0.85 s`，只要高度合格就不会增加这一部分惩罚。

这个时间上限仍然约束迈步频率，但不规定具体抬脚时刻、相位或四脚之间的同步关系。上一步高度不足时，支撑期间也可能继续受罚；该罚分来自历史成绩，不是在要求支撑脚当下抬高。

### 3.3 保留抬脚过高的约束

```python
high_cost = clamp(
    (height - max_height) / (target_height - rest_height),
    0.0, 1.0,
)
high_cost *= actual_airborne & valid_height

per_foot_cost = maximum(cost, high_cost)
raw_cost = 2.0 * per_foot_cost.mean(dim=1)
```

先沿用 `max_height=0.20 m`。取最大值使高度不足、超时和过高约束保持统一的单脚上限。

四足情况下，`2 * mean` 等于 `0.5 * sum`。配合 `weight=-0.25`，整项加权值范围是 `[-0.5, 0]`，与当前对角相位配置下的最大惩罚一致。不要直接对四脚求和，否则最大惩罚会翻倍。

上面的数值尚未乘 `dt`。在当前按时间缩放的 RewardManager 中，`dt=0.02 s` 时，最负的单步奖励贡献为 `-0.01`。

### 3.4 指令门控与状态清理

移动门控沿用当前定义：

```python
active = norm(command_xy) + abs(command_yaw) > 0.1
```

- 门控看指令速度。若乘实际机身速度或足端速度，撞墙停住后可能再次免罚。
- 停止指令时返回零，并清理相关迈步记录。
- 初始化及 reset 时，设置 `last_deficit=0`、`age=0`，给予启动宽限；同时清空峰值、支撑确认和离地标记。
- `reset(env_ids)` 只清理指定环境，不能清空其他环境的记录。
- 所有辅助状态由奖励类自身持有，不修改传感器接触计时、相位、动作历史或其他奖励的缓冲区。
- 每个控制步只更新一次状态。调试显示应读取缓存值，不额外调用有状态奖励的更新函数。

## 6. 续训验证协议

先完成奖励类的边界测试和小规模环境冒烟，再进行 A/B 对照：

| 组别 | 设置 |
| --- | --- |
| A | 当前相位 clearance，权重 `-0.25` |
| B | 本方案 clearance，权重 `-0.25` |

两组从同一 checkpoint 出发，使用相同的优化器恢复方式、训练配置、环境数和采样预算。按相同环境交互步数比较；只有环境数和 rollout 长度相同时，iteration 数才可直接对应。建议至少用 3 个配对种子评估趋势。

先固定 `target_height=0.10`、`max_height=0.20`、`step_window=1.0`、`late_ramp=0.4`。等这个单变量对照明确后，再考虑调整高度、窗口或权重，避免同时改变多个因素。

评测同时覆盖平地、固定高度上下楼梯、低速和转向指令。优先观察：

- 固定台阶通过率，以及失败位置。
- 发生足端立面碰撞后的后退距离和恢复前进所需时间。
- 平地线速度、转向跟踪误差与摔倒率。
- 动作平滑性、落地冲击及滑脚是否恶化。
- 各脚完整迈步间隔、峰值分布、超时占比和支撑误判样本。
- 价值函数损失、解释方差及训练波动。

通过率应要求真正完成台阶段；站在原地未摔倒不算通过。不要只依据 clearance 得分或训练总回报选择模型。

验收目标是越障成功率和碰撞恢复改善，同时平地跟踪、稳定性与落地质量没有明显退化。具体容许退化幅度应在比较结果前确定；小样本或种子间波动较大时，继续评测，不能宣称已经改善。

## 7. 必须保留的限制说明

1. **clearance 合格不等于完成越障。** 抬脚后退回原地也可能获得好成绩；前进、避碰和落地质量仍由速度跟踪、碰撞与其他项共同约束。
2. **`0.10 m` 的间隙目标不保证越过 `15 cm` 台阶。** 还取决于足端前向轨迹、抬脚时机、机身姿态和实际地形几何。
3. **奖励仍带有历史状态。** 约一秒的成绩与计时记忆，未必能被当前短历史观测完整表达。第一轮保持网络接口便于同 checkpoint 对照，但需要观察价值函数学习；若出现明显问题，再单独评估向 critic 提供相关状态，而不是直接扩大第一轮修改范围。
4. **保留 `foot_gait` 就仍有节律偏好。** 本方案解除 clearance 对指定相位脚高的要求，不会立即消除已训练策略对相位的依赖，也不等同于复现原版 HIMLoco。
5. **同一状态下其他奖励计算不变，不代表训练完全没有相互影响。** 奖励改变后，策略会探索不同动作和状态，最终必须通过续训与固定场景评测判断。
6. **只修改奖励再运行旧 checkpoint 的 play，不会让旧策略自动学会新动作。** 新评分规则需要通过训练才能影响策略。
